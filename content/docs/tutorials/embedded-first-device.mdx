Not every device in a lab can run Python. A stage controller, a shutter, a temperature probe or a
pump often sits behind a microcontroller. **arkitekt-esp32** turns an ESP32 into an Arkitekt
[agent](/docs/concepts/terminology/agent) of its own. It registers actions that anyone in your
organization can call from Orkestrator, a script or a workflow, and it publishes live state, with
no computer in between.

<Callout type="warn" title="Experimental">

The embedded client is a working prototype and does not yet have the Python client's feature set.
[What is not there yet](/docs/reference/embedded#what-is-not-there-yet) lists the gaps. The most important ones are: no
cancellation, no TLS certificate verification, and tasks that run synchronously. Use it for lab
prototypes, not for safety-relevant hardware.

</Callout>

## What you need

- An **ESP32** board. The project ships PlatformIO environments for a classic ESP32 dev kit
  (`az-delivery-devkit-v4`, the default) and the **Seeed XIAO ESP32-S3** (`seeed_xiao_esp32s3`).
- [PlatformIO](https://platformio.org/) (CLI or the VS Code extension). The firmware uses the
  **Arduino** framework on `espressif32@6.9.0`.
- The **[Pokket](/docs/guides/apps/pokket)** app on an Android phone, to give the device its
  WiFi credentials and Arkitekt connection over Bluetooth.
- A WiFi network (WPA2 personal or WPA2-Enterprise such as eduroam) from which the device can reach
  your Arkitekt server.

The client is a C++ header library that lives in the firmware project (`src/lib/`), not a packaged
library. Start by cloning the repository and editing `src/main.cpp`.

## A first device

```cpp
#include <Arduino.h>
#include "lib/arkitekt_app.h"

#define LED_PIN 2   // 21 on the XIAO ESP32-S3

ArkitektApp app("my-device", "1.0.0", "default", "My Device");

void registerToggleLed()
{
    auto def = FunctionBuilder("toggle_led", "Toggles the built-in LED", 16, 256)
        .returnInt("pin", "Pin", "GPIO pin toggled")
        .returnBool("state", "State", "New LED state")
        .build();

    app.registerFunction("toggle_led", def,
        [](ArkitektApp &app, Agent &agent, JsonObject args, ReplyChannel &reply) -> bool
        {
            static bool ledState = true;
            ledState = !ledState;
            digitalWrite(LED_PIN, ledState ? HIGH : LOW);

            StaticJsonDocument<256> retDoc;
            JsonObject ret = retDoc.to<JsonObject>();
            ret["pin"] = LED_PIN;
            ret["state"] = ledState;
            reply.done(ret);

            AgentState *st = agent.getState("led_status");
            if (st) st->setPort("on", ledState);   // published live
            return true;
        });
}

void setup()
{
    Serial.begin(115200);
    pinMode(LED_PIN, OUTPUT);

    app.addRequirement("rekuest", "live.arkitekt.rekuest");

    app.registerState("led_status",
        StateBuilder("led_status", "The built-in LED").portBool("on").build());
    registerToggleLed();

    RunConfig cfg;          // BLE provisioning on by default
    app.run(cfg);           // blocks until provisioned and connected
}

void loop()
{
    app.loop();             // WebSocket, background tasks, reset button
}
```

Build, flash and watch the serial log:

```bash
pio run -e seeed_xiao_esp32s3 --target upload
pio device monitor          # 115200 baud
```

On first boot the device advertises itself over Bluetooth as `ARKITEKT_CONFIG`. Open Pokket, choose
the device, and send it your WiFi and the Arkitekt connection. The device connects, registers
`toggle_led` and appears under **Apps** in Orkestrator as `esp32-<adjective>-<noun>-<mac>`.

## Prebuilt firmware

A GitHub Actions workflow in the repository builds merged firmware images for the XIAO ESP32-S3
and the ESP32 dev kit, and publishes them to the [UC2](/docs/concepts/uc2) web flasher. For
your own actions you build from source with PlatformIO as above.

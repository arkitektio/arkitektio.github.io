This page installs a hub with **Konstruktor**, the desktop app. On Linux or macOS you can do the
same from a terminal in one line:

```bash
curl -fsSL https://raw.githubusercontent.com/arkitektio/konstruktor/master/install.sh | sh
```

It installs Konstruktor, asks for a name, and creates and starts a hub. When it shows you a code,
approve it in your browser with your account. The details are in
[Install from the command line](/docs/get-started/deployment/install-cli).

<Prerequisites>

- A machine with Docker that meets the [Requirements](/docs/get-started/deployment/requirements)
- An account on the coordination server, go.arkitekt.live by default
- An idea of what you are installing: [What you are setting up](/docs/get-started/deployment/what-you-are-setting-up)

</Prerequisites>

## Graphical installation [#graphical-installer-recommended]

<Steps>
<Step>

### Download and install Konstruktor

Konstruktor runs on Windows, macOS (one universal build for Intel and Apple Silicon) and Linux
(`.deb`, `.rpm` and AppImage). Install it like any other desktop app.

<DownloadGrid />

</Step>
<Step>

### Let it check Docker

On start, Konstruktor checks for a container engine. If Docker is ready, you land on the home
screen. If not, it tells you what is missing and offers to install the recommended engine (macOS,
Windows) or shows the commands to run (Linux). The check repeats until Docker is ready.

</Step>
<Step>

### Create a hub

Choose **New deployment**, then **Hub**. For a standard install, accept the defaults everywhere
except the folder and the identifier.

| Step | What you decide | Default |
|---|---|---|
| **Docker** | Nothing, this is the engine check again. | |
| **Folder** | Where the deployment lives, and its display name. The folder name seeds the identifier. | `~/MyHub` |
| **Coordination** | Which coordination server the hub trusts for accounts, and the hub's **identifier** (2 to 60 characters, letters, digits, `.`, `_`, `-`). Pick **go.arkitekt.live** (marked *Recommended*) or **Another server** for your institute's own. | go.arkitekt.live |
| **Services** | Which services the hub runs, and whether Rekuest runs here or on a remote host. Per service you can opt to run from source. | rekuest, mikro, fluss, kabinet, kraph |
| **Ports** | The HTTP and HTTPS ports the gateway publishes. Every service is routed behind them (`/rekuest`, `/mikro`, and so on). | 7080 / 7443 |
| **Storage** | Docker volumes (recommended) or the deployment folder for the database and uploaded files. | Docker volumes |
| **Addresses** | How far the hub is reachable (local only, this network, public) and which addresses it advertises to apps. At least one is required. | This network |
| **Mesh** | Whether the hub joins a mesh. See [Mesh](/docs/get-started/deployment/running#join-the-mesh). | No mesh |
| **Review** | A summary of every choice and a preview of the files that will be written. | |

</Step>
<Step>

### Authorize the hub

A hub has no accounts of its own: users, organizations and permissions live on the coordination
server, so the hub must be accepted there before it is written to disk.

1. Konstruktor shows a short code and a link. Open the link.
2. Sign in with your **go.arkitekt.live** account.
3. Pick the organization the hub should belong to, and accept.

When the grant comes back, Konstruktor writes the deployment. This is the same device-code flow apps
use, described in [Service Discovery](/docs/develop/internals/service-discovery).

</Step>
<Step>

### Start it

The wizard writes the deployment and opens the hub's **dashboard**. Press **Start**. On first start
Docker pulls the images, which can take a while depending on your connection.

From the dashboard you can also stop the hub, read logs, open the folder, edit the compose file,
pull updates, back up and restore data, and re-authorize.

The hub is seeded with an `admin` account with a generated password. **Copy admin password** in the
dashboard menu puts it on the clipboard. To create your own user, use the **superuser** dialog on
the dashboard once the hub is running; it creates the account in each service.

Konstruktor stays in the system tray, listing every hub and engine with its run state. Closing the
window stops nothing.

</Step>
</Steps>

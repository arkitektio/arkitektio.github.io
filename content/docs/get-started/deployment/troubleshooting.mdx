---

Each entry below names a symptom, its usual cause and the fix. They assume you installed the hub
with [Konstruktor](/docs/get-started/deployment/konstruktor). Try the [general tips](/docs/guides/troubleshooting#help)
first.

If nothing here helps, open an issue on the
[Konstruktor repository](https://github.com/arkitektio/konstruktor/issues) with the error message,
a screenshot and the logs of the failing service.

## Docker

### Docker Desktop will not install on Windows

**Cause.** Docker Desktop needs administrator rights, a recent 64-bit Windows 10 or 11, and a
virtualization backend.

**Fix.**

1. Without administrator rights, as on many university computers, ask your IT department to
   install Docker for you.
2. Check your Windows version against
   [Docker's system requirements](https://docs.docker.com/desktop/install/windows-install/).
3. Use the WSL2 backend, the default. Check whether WSL2 is installed in PowerShell:

   ```powershell
   wsl --list --verbose
   ```

   If it is not, [install WSL](https://learn.microsoft.com/en-us/windows/wsl/install).

On Linux, follow [Docker's instructions for your distribution](https://docs.docker.com/engine/install/).

### Konstruktor says it cannot find Docker

**Cause.** Docker is not installed, not running, or the `docker` command does not work in your
terminal.

**Fix.** Start Docker. Konstruktor repeats its check until Docker is ready. If it still fails, test
Docker in a terminal:

```bash
docker ps                 # lists running containers, or fails if the engine is not running
docker run hello-world    # proves Docker can pull and run a container
```

If both work and Konstruktor still cannot find Docker, open an issue.

## Konstruktor

### Konstruktor crashes or shows an error

**Cause.** A bug in Konstruktor.

**Fix.** Install the [latest release](https://github.com/arkitektio/konstruktor/releases/latest) by
downloading it again or re-running the install script; there is no auto-updater. If the error
stays, open an issue with a screenshot of the error.

### The hub is never written to disk

**Cause.** Konstruktor writes the deployment only after the coordination server has accepted the
hub. It is still waiting for you to approve it.

**Fix.** Open the link Konstruktor shows, sign in with your account, pick the organization and
accept. If you signed in with the wrong account, sign out on that page and sign in again.

## Starting the hub

### The first start takes very long

**Cause.** Docker pulls every image on the first start. Depending on your connection this takes
several minutes.

**Fix.** Wait. Later starts reuse the images.

### Images cannot be pulled

**Cause.** No internet connection, or a firewall or proxy blocks Docker.

**Fix.** Check the connection. Behind a firewall, allow the Docker daemon to reach the internet.
Behind a proxy, [configure Docker to use it](https://docs.docker.com/network/proxy/).

### A port is already in use

**Cause.** Another program uses one of the ports the hub's gateway publishes, 7080 (HTTP) and 7443
(HTTPS) by default. Every service is routed behind these two.

**Fix.** Stop the other program, or choose other ports in the **Ports** step when you create the
hub. The ports of an existing hub are in its `hub_config.yaml`.

### Permission errors in the deployment folder (Linux)

**Cause.** Konstruktor was run as root once, so the files belong to root.

**Fix.** In the deployment folder, give the files back to your user:

```bash
sudo chown -R $USER:$USER .
```

### A service keeps crashing or never becomes ready

**Cause.** Services need a few minutes on the first start and wait for the services they depend on.
A service that fails for longer has an error in its logs.

**Fix.** Read the logs of that service, in the dashboard or from a terminal:

```bash
konstruktor status lab-hub
konstruktor logs lab-hub --service mikro --tail 200
```

The deployment is an ordinary Docker Compose project, so `docker compose logs <service>` in the
deployment folder works too; the service names are in `docker-compose.yaml`. Restart the service.
If it keeps failing, open an issue with the logs.

## GPU

### Konstruktor does not detect my GPU

**Cause.** Docker cannot run a GPU container. Usually the NVIDIA driver is missing or outdated, or
the GPU does not support CUDA. This is a warning: the hub runs without a GPU, only GPU-accelerated
plugins are affected.

**Fix.**

1. Check that your GPU is on [NVIDIA's list of CUDA GPUs](https://developer.nvidia.com/cuda-gpus).
2. Install the latest [NVIDIA driver](https://www.nvidia.com/Download/index.aspx). On a laptop you
   may need the driver from the manufacturer.
3. Set up GPU support for Docker as described in
   [Arkitekt and the GPU](/docs/get-started/deployment/running#arkitekt-and-the-gpu). You do not need to install
   CUDA or cuDNN yourself; the containers bring them.

If the driver is current and the GPU supports CUDA but the warning stays, open an issue.

## Reaching the hub

### The hub is not in the Assign to hub list

**Cause.** The hub was not accepted on the coordination server, is still starting, or belongs to an
organization your account is not in.

**Fix.** `konstruktor list` shows the hubs on this machine, and `konstruktor status <hub>` what is
running. Sign in with an account that is a member of the hub's organization.

### Orkestrator does not connect to the running hub

**Cause.** Your computer cannot reach any of the addresses the hub advertises.

**Fix.**

1. Check that every service of the hub is running.
2. Restart Orkestrator.
3. On Orkestrator's sign-in screen, open **More Options → Diagnose connection**.
4. If the hub is on another network, make sure the hub and your computer have both
   [joined the mesh](/docs/get-started/deployment/running#join-the-mesh).

### Other computers cannot reach the hub

**Cause.** The hub is set to be reachable only locally, it advertises an address the other computer
cannot resolve, or a firewall blocks the gateway ports.

**Fix.**

1. Check the hub's addresses on its dashboard. They must include one the other computer can reach.
   After changing them, **Authorize** again.
2. Allow incoming connections on the gateway ports (7080 and 7443 by default) in the firewall of the
   hub's machine.
3. For another building, behind NAT or off-site, use the [mesh](/docs/concepts/security/mesh)
   instead of a shared network.

## Updating

### An update does not show up

**Cause.** New images have to be pulled and then started.

**Fix.** Press **Pull images** and then **Start** on the dashboard, or run
`konstruktor pull <hub>` followed by `konstruktor up <hub>`. Konstruktor has no channel picker: a
hub's channel is the set of image tags in its `hub_config.yaml`. See
[Update a hub](/docs/get-started/deployment/running#update-a-hub).

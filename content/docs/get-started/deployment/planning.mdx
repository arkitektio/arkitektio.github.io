Arkitekt runs on anything from a single machine to a cluster or the cloud. This page covers the
questions that decide how big your hub has to be. Who runs which server, and how apps reach it, is
covered in [Where Arkitekt runs](/docs/get-started/deployment/topology). To set up a first hub, start
with [What you are setting up](/docs/get-started/deployment/what-you-are-setting-up).

<Callout type="warn" title="On the production readiness of Arkitekt">

Arkitekt is at an early stage of development, and we are still making it secure and scalable. For
now we discourage using it in a multi-user environment. If you want to, please contact us: we would
like to know how you use Arkitekt. The considerations below are what to think about if you do.

</Callout>

## How many users will use Arkitekt?

If you are the only user, or your team is small (say, fewer than 20 people), one machine is enough,
and you need not worry about redundancy or scaling. For a larger team, or to open Arkitekt to the
public, consider a cluster or the cloud, and please contact us.

## How much data will be stored in Arkitekt?

Image data lives in an S3-compatible object store (MinIO in the standard setup), which supports
several storage providers and strategies such as
[tiering](https://min.io/product/automated-data-tiering-lifecycle-management). Most labs will want a
mix of "hot" storage, which is fast and expensive, and "cold" storage, which is slow and cheap. How to
configure storage for Mikro is described in [Mikro: Storage](/docs/develop/internals/mikro#storage).

## How much data will be streamed through Arkitekt?

If you stream a lot of data to and from the hub, you need a fast network connection with enough
bandwidth, and fast storage. The workflows in our publication all ran over a 1 Gbit/s connection,
which may not be enough for your use case. The critical part is the object store, because every
streamed image passes through it. For small teams the API layer is rarely the limit.

## How much compute will be required?

Most computation happens in the apps, on whatever machines they run on. If you run plugin apps on
the hub's own Docker host, that host needs the compute for them.

<Callout type="info" title="Plugin apps and GPUs">

Sharing GPUs between plugin apps is only partly supported so far, and we plan to improve it with the
Kabinet service. If you want to run several GPU-heavy plugin apps, make sure you have enough GPUs.
How GPUs are made available to containers on each operating system is described in
[Arkitekt and the GPU](/docs/get-started/deployment/running#arkitekt-and-the-gpu).

</Callout>

## How you install it

Konstruktor, as a desktop app or a command line tool, installs and manages a hub; see
[Install your first hub](/docs/get-started/deployment/first-hub). Running the Docker Compose project without
Konstruktor, and the state of the Helm chart for Kubernetes, are described in
[Other installation strategies](/docs/get-started/deployment/other-installation-strategies).

The Rust client follows the same model as the [Python client](/docs/developers/python): an **app**
declares **actions**, `run(app)` connects it as an [agent](/docs/design/terminology/agent), and the
platform calls it. Use it when you want a small, fast, self-contained binary: a device driver, a
camera server, or an agent on a machine where you would rather not install Python.

<Callout type="info" title="Pre-1.0">

The crates are at **0.2** and still change in breaking ways between minor versions. The feature set
is smaller than Python's. Most notably, there are no [workflows](#durable-execution), so a Rust action
cannot call other actions yet. [Status](#status) lists what is and is not implemented.

</Callout>

## Install

```toml
[dependencies]
arkitekt = "0.2"
mikro = { package = "arkitekt-mikro", version = "0.2" }   # only if you use mikro
tokio = { version = "1", features = ["macros", "rt-multi-thread"] }
anyhow = "1"
futures = "0.3"                                           # for streaming actions
```

Apps normally depend on `arkitekt` and on the service crates they use. `arkitekt` re-exports the
lower-level crates (`fakts`, `rath`, `rekuest`) and the macros. Some crates are published under a
prefixed name because the plain name was taken on crates.io, but you import them under the short
name:

| Crate on crates.io | Import as | What it is |
|---|---|---|
| `arkitekt` | `arkitekt` | `App`, `run`, `connect`, `easy`, `serve`, and re-exports of everything below |
| `rekuest` | `arkitekt::rekuest` | ports and types, the agent, `Task`, states and locks, the journal |
| `rekuest-macros` | via `arkitekt` | `#[action]`, `#[arkitekt::service]`, `#[derive(State)]` |
| `fakts` | `arkitekt::fakts` | server discovery and authentication |
| `arkitekt-rath` | `arkitekt::rath` | an authenticated GraphQL client |
| `arkitekt-mikro` | `mikro` | the [Mikro](/docs/design/services/mikro) client: array datasets as zarr on S3 |
| `arkitekt-lovekit` | `lovekit` | LiveKit broadcasts and video streams |

The runtime is built on **tokio**. Enable `arkitekt`'s `serve` feature to [serve an app over
HTTP](#serving-without-a-server), and `mesh` / `mesh-native` to reach services on the
[mesh](/docs/design/security/mesh).

## A first app

```rust
use std::time::Duration;

use arkitekt::{action, run, App, Task};
use futures::Stream;

/// Greet someone
///
/// Says hello, possibly several times.
///
/// # Arguments
/// * `name` - Who to greet
/// * `times` - How often
///
/// # Returns
/// The greeting
#[action]
async fn greet(name: String, #[port(default = 1)] times: i64) -> String {
    format!("Hello {name}! ")
        .repeat(times.max(1) as usize)
        .trim_end()
        .to_owned()
}

/// Count
///
/// Yields every number up to `to`, one per second.
///
/// # Arguments
/// * `to` - Where to stop (exclusive)
#[action]
async fn count(to: i64, task: Task) -> impl Stream<Item = i64> {
    futures::stream::unfold(0, move |i| {
        let task = task.clone();
        async move {
            if i >= to {
                return None;
            }
            tokio::time::sleep(Duration::from_secs(1)).await;
            task.progress((100 * (i + 1) / to.max(1)) as i32, format!("at {i}"));
            Some((i, i + 1))
        }
    })
}

#[tokio::main]
async fn main() -> anyhow::Result<()> {
    let app = App::new("hello-rust", "0.1.0")
        .description("Says hello from Rust")
        .action(greet)
        .action(count);

    run(app).await
}
```

Nothing connects until `run(app)` is awaited. On first run it prints a URL and a code to the
terminal. Open the URL, confirm the code and authorize the app. The credential is cached, so later
runs connect straight away. `greet` and `count` then show up in Orkestrator like any Python action.
`count` streams: each item reaches the caller as it is yielded.

## `#[action]`

`#[action]` turns a function into an action. The function is replaced by a unit struct of the same
name, which is what you pass to `App::action`. The original body stays callable as `greet::call(..)`,
which is useful in tests, and `greet.definition()` returns the definition the platform will see.

**Documentation.** The first paragraph of the doc comment is the action's name and description.
Bullets under `# Arguments` describe the ports, and `# Returns` describes the result. An action
with no doc comment is registered as *in development*.

**Parameters** are one of four kinds:

| Parameter | Is |
|---|---|
| any type implementing `PortType` | an input port |
| `task: Task` | the running [task](/docs/design/terminology/task), injected |
| `StateMut<T>` / `StateRef<T>` | a handle to one of the app's [states](#state-and-lifecycle), injected |
| `#[inject] x: T` | a value from the app's context, usually a service client such as `Mikro` |

`#[port(default = .., description = "..", label = "..")]` configures a single port. A default also
makes the port nullable. The port name `value` is reserved.

**Ports come from Rust types:**

| Rust type | Port |
|---|---|
| `String` | string |
| `bool` | boolean |
| `i8`…`i64`, `u8`…`u64`, `isize`, `usize` | integer |
| `f32`, `f64` | float |
| `chrono::DateTime<Utc>` | date |
| `Option<T>` | `T`, nullable |
| `Vec<T>` | list of `T` |
| `HashMap<String, T>` | dict of `T` |
| a type implementing `Structure` | a [structure](/docs/design/terminology/structure), passed by id (e.g. `mikro::ArrayDataset`) |
| `Memory<T>` where `T: MemoryStructure` | an object kept in this agent's memory; only its id travels |

**Returns.** A value is the single output, a tuple gives one output per element, and `()` gives
none. `Result<T, E>` is unwrapped, and an `Err` fails the task with its message. Returning
`impl Stream<Item = T>` makes the action a **generator**. A non-`async` function runs on tokio's
blocking thread pool.

**Options:** `#[action(name = "..", description = "..", collections = [..], locks = [..],
concurrency = "serial" | "parallel", auto_locks = false)]`.

### The task

| `Task` method | |
|---|---|
| `progress(percent, message)` | progress, shown live |
| `log(message)`, `log_level(level, message)` | a log line on the task |
| `pausepoint().await` | pause here if a person paused the task |
| `now()`, `random(n)`, `sleep(d).await` | time, randomness and sleeping, **recorded** in the journal ([durable execution](#durable-execution)) |
| `id()`, `user()`, `org()` | who and what this task is |
| `Task::local()` | a stand-in for calling an action directly in tests |

## State and lifecycle

A struct deriving `State` is published to the platform. Orkestrator shows it live, and each change
is sent as a JSON patch. Field doc comments become the field descriptions.

```rust
use arkitekt::{action, App, State, StateMut, Task};
use serde::{Deserialize, Serialize};

#[derive(Debug, Clone, Default, Serialize, Deserialize, State)]
#[state(name = "CameraState", locks = ["camera"])]
struct CameraState {
    /// Whether the camera is connected
    connected: bool,
    /// Exposure time in milliseconds
    exposure_ms: f64,
    /// Frames acquired so far
    frames: i64,
}

#[action]
async fn acquire(
    #[port(default = 3)] count: i64,
    camera: StateMut<CameraState>,
    task: Task,
) -> anyhow::Result<i64> {
    for i in 0..count {
        task.pausepoint().await;
        let exposure = camera.read(|c| c.exposure_ms);
        tokio::time::sleep(std::time::Duration::from_millis(exposure as u64)).await;
        camera.update(|c| c.frames += 1)?;
        task.progress((100 * (i + 1) / count.max(1)) as i32, format!("frame {}", i + 1));
    }
    Ok(camera.read(|c| c.frames))
}

let app = App::new("camera", "0.1.0")
    .state(CameraState::default())
    .startup(|startup| async move {
        startup.set_state(CameraState { connected: true, exposure_ms: 10.0, frames: 0 })?;
        Ok(())
    })
    .shutdown(|_| async move { Ok(()) })
    .action(acquire);
```

- `StateMut<T>` has `get()`, `read(|s| ..)`, `update(|s| ..)` and `set(v)`. `StateRef<T>` reads only.
- **Locks:** an action that takes a state holds that state's locks while it runs, so two tasks
  cannot drive the camera at once. Pass `auto_locks = false` to opt out, or `concurrency =
  "parallel"` for actions that are safe to run side by side.
- **Hooks:** `.startup(..)` runs before the first task and can `set_state` and `set_context`.
  `.background(..)` runs for as long as the app does, and may change only states that need no lock.
  `.shutdown(..)` runs on the way out. Each hook returns `anyhow::Result<()>`.
- State fields should be plain values, not structures. Don't write "getter" actions that only return
  a state: the state is already published.

## Services and scripts

A service client is built from the server's configuration when the app connects. Add the service
to the app and take the client with `#[inject]`:

```rust
use arkitekt::{action, run, App, Task};
use mikro::{axes_for, ArrayDataset, Mikro};

/// Invert Image
///
/// Inverts a 16-bit image.
///
/// # Arguments
/// * `image` - The image to invert
///
/// # Returns
/// The inverted image
#[action]
async fn invert_image(
    image: ArrayDataset,
    #[inject] mikro: Mikro,
    task: Task,
) -> anyhow::Result<ArrayDataset> {
    task.progress(10, "downloading");
    let data = mikro.read_array::<u16>(&image, 0).await?;
    let inverted = data.mapv(|v| u16::MAX - v);
    task.progress(60, "uploading");
    let axes = axes_for(
        &image
            .axis_names
            .iter()
            .map(String::as_str)
            .collect::<Vec<_>>(),
    );
    Ok(mikro
        .create_array_dataset(&format!("{} (inverted)", image.name), &inverted, axes)
        .await?)
}

#[tokio::main]
async fn main() -> anyhow::Result<()> {
    run(App::new("inverter", "0.1.0").service(mikro::service).action(invert_image)).await
}
```

`ArrayDataset` is a structure. The caller passes an id, and the agent expands it into the dataset
before your function runs. Adding `mikro::service` also declares the requirements (Mikro and its S3
store) that the user approves when the app first connects.

**Scripts** that only call the platform use `easy` and `connect`, the Rust twin of Python's
[`easy`](/docs/developers/python/scripts):

```rust
use mikro::{axes_for, Mikro};
use ndarray::ArrayD;

#[tokio::main]
async fn main() -> anyhow::Result<()> {
    let rt = arkitekt::easy("rusty-script", "0.1.0")
        .service(mikro::service)
        .connect()
        .await?;
    let mikro = rt.require::<Mikro>()?;

    let data: ArrayD<f32> = ArrayD::from_shape_fn(vec![64, 64], |ix| (ix[0] * ix[1]) as f32);
    let image = mikro.create_array_dataset("gradient", &data, axes_for(&["y", "x"])).await?;
    println!("created {} with shape {:?}", image.id, image.shape);
    Ok(())
}
```

Mikro stores axes ordered time → channel → space. `axes_for` maps `t`, `c`, `z`/`y`/`x` to those
kinds. For operations the crate does not wrap, `mikro.rath()` gives the authenticated GraphQL
client.

**Your own service** is a function annotated with `#[arkitekt::service]`. This is how the `mikro` crate defines its own. Its `#[require(..)]`
parameters name the server-side services it needs, and it returns the client that is put into the
context:

```rust
#[arkitekt::service(name = "mikro")]
pub fn service(
    #[require("live.arkitekt.mikro", "Where the user's images and their metadata live")]
    mikro: Alias,
    #[require("live.arkitekt.s3", "Where the user's files are stored")] s3: Alias,
    fakts: Fakts,
) -> anyhow::Result<Mikro> {
    let rath = Rath::from_alias(&mikro, "graphql", Arc::new(fakts))?;
    Ok(Mikro::new(rath, DataLayer::from_alias(&s3)))
}
```

## Connecting

| Variable | Effect |
|---|---|
| `FAKTS_URL` (or `ARKITEKT_URL`) | The server. Defaults to `https://go.arkitekt.live`. |
| `FAKTS_TOKEN` | `client_id:refresh_token`: connect without the device-code prompt, e.g. in a container |
| `FAKTS_ALLOW_INSECURE_TRANSPORT=1` | Allow plain `http://` to a non-loopback server |
| `ARKITEKT_DEVICE_ID` | Override this machine's identity |
| `ARKITEKT_MESH=1` / `native`, `ARKITEKT_MESH_PROXY` | Reach services that are only on the [mesh](/docs/design/security/mesh) |

For more control, build `ConnectOptions` (`.url(..)`, `.no_cache()`, `.force()`) and use
`app.connect_with(opts)`. Credentials are cached per app and server under your state directory
(e.g. `~/.local/state/arkitekt/cache/`, readable only by you). The file is separate from the Python
client's cache, because both rotate their refresh tokens.

## Serving without a server

With the `serve` feature, an app can be served straight from an [axum](https://github.com/tokio-rs/axum)
router, without any Arkitekt server. That is useful for embedding a device API in a local service,
or for testing:

```rust
use arkitekt::{serve, ServeOptions};

let router = axum::Router::new();
serve(app, router, ServeOptions::default()).await?.listen("0.0.0.0:8099").await
```

Every action becomes `POST /{interface}` (`curl -X POST localhost:8099/acquire -d '{"args": {"count": 3}}'`).
Tasks can be cancelled, paused and resumed, states are available under `/states`, a websocket at
`/ws` streams everything live, and `/docs` serves interactive OpenAPI docs. An app without services
never authenticates in this mode.

## Durable execution [#durable-execution]

The Rust agent implements the delivery half of [durable
execution](/docs/design/architecture/durable-execution), but not the workflow half yet.

**What it does:**

- It keeps a local **write-ahead journal** (SQLite, `<app>.journal.db` in the working directory)
  of every task event and state change, in one order. Anything the server has not acknowledged is
  re-sent after a reconnect or a restart.
- It records `task.now()`, `task.random(n)` and `task.sleep(d)` as effects in the journal. This is
  the groundwork for replay.

**What it does not do yet:**

- Rust actions register as **plain** actions with no `effects` claim. If the agent dies while a
  task runs, the task ends **LOST** and the caller decides, as for any plain Python action.
- There is no `#[workflow]`, no `task.call`, and no `task.record` / `retry` / `hold` / `guard`.
  Orchestration that must survive a crash belongs in a
  [Python workflow](/docs/developers/python/durable-execution), which can call Rust actions like any
  others.

## Status [#status]

| Implemented | Not yet |
|---|---|
| Discovery, device-code login, rotating refresh tokens, cache | The redeem grant for headless deployment (use `FAKTS_TOKEN`) |
| `#[action]` with typed ports, defaults, docs, structures, tuples, `Result` and streams | Workflows (actions calling actions) and `effects` claims |
| Cancel, interrupt, pause/resume/step, progress, logs, reconnect with backoff | GraphQL subscriptions |
| States with locks, startup/background/shutdown hooks | Structures inside states |
| The write-ahead journal and resend after restart | Other Mikro data types (tables, files, meshes) and multiscale pyramids |
| Memory structures | Clients for other services (unlok, fluss, kabinet, …) |
| Mikro array datasets, LiveKit streams | |
| Serving over HTTP, tested against the Python implementation | |

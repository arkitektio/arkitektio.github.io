Python is the reference implementation of the Arkitekt client. Every feature of the platform is
available from Python first, and the other clients follow its model. This section documents the
`arkitekt` package (version 5 and later, Python 3.11+).

<Callout type="warn" title="Coming from arkitekt-next?">

Earlier versions of these docs described the `arkitekt_next` package, with `easy(...)` as the app,
`@register` as the decorator and an `arkitekt-next` command. That package has been replaced by
`arkitekt`. The [installation page](/docs/developers/python/installation#migrating-from-arkitekt-next)
has a table mapping every old name to the new one.

</Callout>

## Two directions

A Python program uses Arkitekt in one of two directions, and the library has a different entry point
for each:

| Direction | You write | Entry point | It runs… |
|---|---|---|---|
| **Offer** actions others can call | an `App` with `@app.action` functions | `run(app)` or `arkitekt run dev` | until you stop it, waiting for tasks |
| **Call** the platform | a script or notebook | `easy("name", service, …)` | as long as your script does |

Most of this section is about the first direction, because that is how your code becomes part of
the platform. The second is covered in [Scripts & notebooks](/docs/developers/python/scripts).

```python
from arkitekt import App, run

app = App("hello", "0.1.0")


@app.action
def greet(name: str = "world") -> str:
    """Greet

    Says hello.
    """
    return f"Hello {name}!"


if __name__ == "__main__":
    run(app)
```

These few lines give you a `Greet` action. It shows up in Orkestrator with a generated form, anyone
in your organization can call it, and it can be wired into workflows.

## How the library is layered

`arkitekt` is the package you install and import. Underneath, three libraries do the work:

| Package | Role |
|---|---|
| `arkitekt-spec` | The **declaration** layer: the app registry, the `Task` protocol, `Effects`, `Execution`, the errors. It does no I/O. |
| `arkitekt-runtime` | The **execution** core: actors, the concrete task, the journal, state publishing and replay. |
| `rekuest` | The **distributed runtime**: the websocket agent that talks to the [Rekuest](/docs/design/services/rekuest) service, and the client for calling actions. |

`arkitekt` re-exports everything an app author needs, so `from arkitekt import …` is the only
import you should need for the app itself. Service clients (`mikro`, `fluss`, `elektro`, …) are
imported from their own packages.

## Reading order

1. **[Installation](/docs/developers/python/installation)**: install the library and connect to a
   server.
2. **[Core concepts](/docs/developers/python/concepts)**: the vocabulary (app, action,
   implementation, agent, task, structure, state), each with a short example. Read this before the
   guides.
3. **[Your first app](/docs/developers/python/first-app)**: scaffold a project with the CLI and run
   it in development mode.
4. **[Types & data](/docs/developers/python/types)**: what can cross an action boundary, and how
   images and other large data travel by reference.
5. **[State & lifecycle](/docs/developers/python/state-lifecycle)**: startup hooks, live state,
   shared context and background tasks.
6. **[Workflows](/docs/developers/python/workflows)**: actions that call other apps' actions.
7. **[Durable execution](/docs/developers/python/durable-execution)**: what happens when an agent
   dies mid-task, and how to write workflows that survive it.
8. **[Scripts & notebooks](/docs/developers/python/scripts)**: calling the platform without
   offering anything.
9. **[Packaging](/docs/developers/python/build)**: turn the app into a container others can install.

## Before you start

- **Python 3.11 or newer.**
- **A reachable Arkitekt server.** Either [join an existing one](/docs/introduction/installation/joining)
  or [start your own](/docs/introduction/installation/starting-new).
- **The terminology.** The [terminology pages](/docs/design/terminology) define the platform-wide
  terms. The [core concepts](/docs/developers/python/concepts) page shows what each one looks like
  in Python.

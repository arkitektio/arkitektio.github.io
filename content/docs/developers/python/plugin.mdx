So you want to provide some functionality for Arkitekt?

**THANK YOU!** We are always looking for new Apps and Actions to be added to the Arkitekt Ecosystem.
This guide will help you get started with creating your first App and Action.

This tutorial assumes you have a basic (really basic) understanding of the command line
and have arkitekt installed on your computer. If you don't have arkitekt installed, check out the [installation guide](/docs/introduction/installation).

## Creating a new Apps

The integrated Style revolves around the concepts of Apps. So lets create one. Open up your terminal in a *new folder*, where you 
want to create your new app and run :

```bash
arkitekt-next init
```

This should start an installation wizard, which will guide you through the process of creating a new app and will ask you a few questions
about your app. Your [Manifest](/docs/design/terminology/manifest).

<Terminal src={"/casts/init.cast"} />
<div className="mt-2"></div>

A few words about the questions asked in the wizard, no worries you can always change them later.

- **App Identifier** - This is the name of your app. This should be a unique name, which identifies your app. Think of something cool,
    like `stardist` or `kalkulator`. It should be something that your users will remember.

- **App Description** - This is a short description of your app. It should be a short sentence, which describes what your app is best at.
   No need to describe your functionality here (thats what Actions are for), but rather why you designed your app.

- **Scopes** - [Scopes](/docs/design/security/measures), will give your apps certain rights to do things on your behalve ( like accessing your images),
    so you should only give your app the scopes it really needs right now. You can always add more scopes later. These scopes will be also asked
    when others will want to install your app. So make sure you only ask for the scopes you really need.

- **Logo** - This is the logo of your app. You can either choose a local path relative to your app folder or a url to an image. The image
    will be displayed in the (soon to come) app store and when others use your app.

- **Author** - This is the author of your app. This can be your name or the name of your company. By default it will use your username, but you can
    change it to whatever you want.


Once you are done, you should see a new folder called `.arkitekt` in your current directory. As well as a new file called `app.py`.
These are the main files that make your app. Lets inspect them both.

## The .arkitekt folder

The `.arkitekt` folder contains all the configuration files for your app. It will grow some more files once you build and publish your app,
but for now it mainly contains `manifest.yaml`, the [Manifest](/docs/design/terminology/manifest) of your app: its name, version and entrypoint,
but also which rights it needs and how it should be built and deployed. Once you delete your `.arkitekt` folder, your app will be gone.
So make sure you don't do that !

```yaml
author: jhnnsrs
entrypoint: app
identifier: demo
requirements: []
scopes:
  - read
version: 0.0.1
```

So far the app only asks for very basic access rights (it can read data from the platform, but not write to it) and declares no
requirements. Requirements let you declare hardware and software needs for when the app is deployed as a PluginApp; we will
change both later. The folder also contains a `.gitignore` and a `.dockerignore`, which keep cached secrets (such as access tokens)
out of your git repository and docker image. Do not delete them.

<Callout type="info" title="I don't see the .arkitekt folder">

The `.` prefix hides the folder in most file explorers, just like `.git`. Most IDEs show hidden files by default, and you
can always use the terminal to navigate into it.

</Callout>

## The app.py file

This is the main file of your app. And the entrypoint that the CLI will call when running your App.
It is a python file, that contains all the [Actions](/docs/design/terminology/action) of your app. Lets open it up

```python
from arkitekt_next import register

@register
def hello_world(name: str) -> str:
    """Hello World

    This is a simple Hello World Action, that will greet you by your name.
    and print it to the console.

    Args:
        name (str): Your name

    Returns:
        str: A greeting
    """
    greeting = f"Hello {name}"
    print(greeting)
    return greeting
```

This is the default code that is generated for you. It contains a single function that defines and implements the
"Hello World" Action [Action](/docs/design/terminology/action). It's pretty straightforward but let's break it down:

```python
from arkitekt_next import register
```
This import is what makes this Python code an Arkitekt app. `register` is a decorator that can mark any function in your app as an Action.
You can have as many Actions as you want in your app, and once you run your app, they will become available on the Arkitekt Server and 
can be used by others.

<Callout type="info" title="A few things to note">

- `app.py` should **not** contain code that runs when the file is imported, only functions to register. Anything at module
  level runs every time a user runs your app (or every time you save the file in dev mode). Guard one-off code with
  `if __name__ == "__main__":`.
- `app.py` should **not** create an app instance itself (no `easy("app", "version")`); the CLI creates it when it runs your app.

</Callout>

Lets do just that, lets run our app. Once it runs, head over to [Adapting our real App](/docs/developers/python/more) for a first
real Action working on an image.

## Interlude

Before we can run our app, we will need to start our Arkitekt Server and make sure our app can connect to it. Please make sure you installed
an Arkitekt Server and have it running. For strategies of how to do that, check out the [installation guide](/docs/introduction/installation).

## Running your app

Open up your terminal and run:

```bash
arkitekt-next run dev --url localhost:8000
```

This will start your app in development mode and connect it to your local Arkitekt Server. You should see something like this:

<Terminal src={"/casts/init.cast"} />
<div className="mt-6"></div>

<Callout type="info">


If you are running your Arkitekt Server on a different port or host, you will need to change the `--url` parameter accordingly.
You don't need to specify any protocol, as the CLI will try to autodetect it. If you omit the `--url` parameter, it will default to `localhost:8000`
the default port of the Arkitekt Server.


</Callout>

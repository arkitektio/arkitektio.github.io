title: "Bloks: UIs from JSX"
description: "Contribute declarative dashboard panels to the platform with app.blok: a component tree wired to your own and other apps' actions and state."
---

A **blok** is a declarative UI panel your app contributes to the platform. It is a small
dashboard built from a component tree and wired directly to actions and state. A plugin app has no
window of its own, so bloks are how it gets a UI: Orkestrator renders them.

You write a blok as a JSX-like XML string (BSX) and declare it on your `App`, next to your actions:

```python
from arkitekt import App

app = App("camera", "0.1.0")

# ... @app.state class CameraState, @app.action def snap(...) ...

app.blok(
    "camera_panel",
    """
    <Page>
      <Label text="Camera" />
      <Text value="$state.camera.connected" />
      <Button title="Snap" onClick="@camera.snap(exposure_ms=10)" />
    </Page>
    """,
    description="Camera dashboard",
)
```

The string is parsed when the blok is declared, and syntax errors are reported with line and column
numbers. `bsx(...)` parses a string on its own, if you want to build or test a tree separately.

## The component catalog

Bloks are composed from a catalog of components the platform ships. These are layout and
display primitives you nest to build a panel:

| Component  | Purpose                                              |
| ---------- | ---------------------------------------------------- |
| `Page`     | The root container of a blok.                        |
| `Stack`    | Lays its children out vertically or horizontally.    |
| `Label`    | A static text label.                                 |
| `Text`     | Displays a (usually bound) value.                    |
| `Button`   | Triggers an action callback when clicked.            |
| `Image`    | Renders an image structure.                          |

## Wiring props to your app

Props follow three conventions, which is what ties a blok to the rest of your app:

| Prop value                               | Meaning                                                                                                   |
| ---------------------------------------- | --------------------------------------------------------------------------------------------------------- |
| `text="Camera"`                          | A **static** value.                                                                                       |
| `value="$state.camera.connected"`        | A **dynamic binding** to a dependency's state (`$state.<dependency>.<path>`).                              |
| `onClick="@camera.snap(exposure_ms=10)"` | An **action callback** that calls a dependency's action (`@<dependency>.<operation>(...)`). Use `@utils.<op>(...)` for built-in utilities. |

Bloks derive their action and state dependencies from the paths they reference, so the platform
knows exactly what each panel needs. Paths that name **this app's** states and actions are inferred.
To bind to **another** app, declare it as a protocol with
[`@app.declare`](/docs/developers/python/workflows#1-say-what-you-need-appdeclare) and pass it under
the key the tree uses:

```python
app.blok(
    "stage_panel",
    '<Page><Text value="$state.stage.position.x_um" /></Page>',
    dependencies={"stage": StageProtocol},
)
```

## Declaring a blok

| `app.blok(...)` argument | Meaning |
|---|---|
| `name` | The blok's name |
| `component` | The tree, as a BSX string or an already parsed tree |
| `description` | What the blok shows |
| `demo_state` | State to render the blok with when there is none (for previews) |
| `dependencies` | Other apps' protocols the tree uses, by key |
| `catalog` | A UI catalog to validate the tree against, declared with `app.ui_catalog(...)` |

The blok is registered when the app runs, like its actions. `arkitekt inspect all` lists it together
with the rest of the app.

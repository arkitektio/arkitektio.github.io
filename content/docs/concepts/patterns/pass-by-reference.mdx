An image of a few gigabytes does not belong in a message. In Arkitekt it is stored once, in a data
service such as [Mikro](/docs/concepts/services/mikro), and what travels between apps, through
workflows and into the task history is a **reference**: a typed id.

```python
@app.action
def denoise(volume: Volume, mikro: Mikro) -> Volume:
    """Denoise"""
    source = volume.data                     # expanded: a lazy array, fetched chunk by chunk
    result = mikro.create_array_dataset(...) # stored once
    return result.lens()                     # only the reference goes back
```

`Volume` is a **structure**: a type the platform knows how to *shrink* to an id when it leaves an
action and *expand* back into an object when it arrives. The caller passes an id, your function
gets an object with lazy access to the data, and your return value is shrunk to an id again.

## The pattern

This is the **claim check** pattern from enterprise integration: store the payload, pass a ticket
for it, and let whoever needs the payload redeem the ticket. Arkitekt adds types to the ticket. A
`Volume` is not just "some id in Mikro" but "an array dataset with exactly three spatial axes", so
forms only offer fitting datasets and the workflow editor can check that one step's output fits the
next step's input.

Three kinds of reference cover different distances:

| Kind | Lives | Resolves |
|---|---|---|
| A service structure (`Volume`, `SingleChannelTrace`, …) | in a data service | for every app that can reach the service |
| A registered structure (`app.register_structure(...)`) | wherever your expander fetches it from | for every app that registers the same type |
| A memory structure (`app.memory_structure(...)`) | in the memory of one agent | only inside that agent's process |

## What it buys

- **Messages stay small.** Tasks, workflow journals and provenance records hold ids, not
  gigabytes. That is what makes it cheap to record everything.
- **Data is read only where it is used.** A lazy array fetches only the chunks an action touches,
  and two actions in a row on another machine do not copy the volume through the server.
- **Provenance has something to point at.** A stored dataset has an identity, so the platform can
  record that this mask was derived from that image (`derived_from=`), by this task.
- **Types carry meaning.** Requirements on a structure (three spatial axes, one channel) narrow a
  reference by features of the object it points to, which its class cannot express, and are checked
  before a step runs, not when it fails halfway. See
  [Requires & provides](/docs/guides/python/requires-provides).

## What it costs

- **An extra hop.** Expanding a reference is a fetch. For small values, a plain port (`float`,
  `@app.model`) is simpler and faster.
- **The store must be reachable** by every app that expands the reference. Across sites, that is
  what the deployment's mesh is for.
- **A memory reference lives and dies with its agent.** The object stays in the agent's memory
  until it is collected or the agent stops, so memory grows with every run, and the reference
  works only on that one agent. That makes the app stateful. Use it sparingly: fusing the steps
  into one action, or storing the result, is usually better. See
  [Arrays between actions](/docs/guides/python/examples/in-memory#use-it-sparingly).

<Callout type="info" title="The short version">
We use AI heavily to build Arkitekt. We never ship code we don't understand.
Nothing here is vibe-coded.
</Callout>

## Looks are deceiving

Arkitekt looks like a lot of software that was generated in an afternoon and
never read again. The modern surface, the animations, the polish. All of it is
exactly the aesthetic that has come to signal "AI slop".

So let's be honest about it. Yes, there is AI all over this project. We use it a
lot, especially in building the new version. It drafts code, it drafts docs, it
helped with the very page you are reading. Pretending otherwise would be silly.

But polish is not proof of carelessness, and using AI is not the absence of it.
The appearance and the reality point in opposite directions here.

## What we don't do

We don't *vibe-code*. We don't generate a feature, watch it compile, and merge it
because the demo looked fine. Every line that lands in Arkitekt is read,
understood, and owned by a human who could have written it themselves and can
explain why it is there.

<Callout type="warn" title="No unsupervised code">
AI never merges to Arkitekt on its own. There is always a human in the loop who
reviews, questions, and takes responsibility for the result. If we can't explain
a piece of code, it doesn't ship.
</Callout>

Scientific software carries a particular weight. People make decisions about real
experiments and real data based on what it does. "The model probably got it
right" is not an acceptable standard for a platform that sits between a
microscope and a conclusion.

## Where we use it

We use AI where it genuinely makes us faster without making us dumber:

- **Drafting.** First passes of components, migrations, and boilerplate that we
  then rewrite, tighten, and review.
- **Refactoring.** Large mechanical changes across the codebase, always checked
  diff by diff.
- **Docs.** Turning our notes and design decisions into readable pages like this
  one, edited by us afterwards.
- **Exploration.** Trying three approaches quickly to find the one worth keeping.

In every case the AI is an accelerator, not an author of record. The judgment,
the architecture, and the responsibility stay with the people building Arkitekt.

## Why this matters for you

If you build on Arkitekt, you are trusting it with data and decisions. You should
know that its polished look is not a shortcut. It is the result of using powerful
tools *under supervision*, the same way we would expect any careful engineer to
use them.

We think that is the honest place to stand on AI. We neither pretend it away, nor
let it run unattended. Use it heavily. Supervise it always.

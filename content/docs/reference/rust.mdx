Reference for the Rust client introduced in [Your first Rust app](/docs/tutorials/rust-first-app).

## `#[action]`

`#[action]` turns a function into an action. The function is replaced by a unit struct of the same
name, which is what you pass to `App::action`. The original body stays callable as `greet::call(..)`,
which is useful in tests, and `greet.definition()` returns the definition the platform will see.

**Documentation.** The first paragraph of the doc comment is the action's name and description.
Bullets under `# Arguments` describe the ports, and `# Returns` describes the result. An action
with no doc comment is registered as *in development*.

**Parameters** are one of four kinds:

| Parameter | Is |
|---|---|
| any type implementing `PortType` | an input port |
| `task: Task` | the running [task](/docs/concepts/terminology/task), injected |
| `StateMut<T>` / `StateRef<T>` | a handle to one of the app's [states](/docs/guides/rust#state-and-lifecycle), injected |
| `#[inject] x: T` | a value from the app's context, usually a service client such as `Mikro` |

`#[port(default = .., description = "..", label = "..")]` configures a single port. A default also
makes the port nullable. The port name `value` is reserved.

**Ports come from Rust types:**

| Rust type | Port |
|---|---|
| `String` | string |
| `bool` | boolean |
| `i8`…`i64`, `u8`…`u64`, `isize`, `usize` | integer |
| `f32`, `f64` | float |
| `chrono::DateTime<Utc>` | date |
| `Option<T>` | `T`, nullable |
| `Vec<T>` | list of `T` |
| `HashMap<String, T>` | dict of `T` |
| a type implementing `Structure` | a [structure](/docs/concepts/terminology/structure), passed by id (e.g. `mikro::ArrayDataset`) |
| `Memory<T>` where `T: MemoryStructure` | an object kept in this agent's memory; only its id travels |

**Returns.** A value is the single output, a tuple gives one output per element, and `()` gives
none. `Result<T, E>` is unwrapped, and an `Err` fails the task with its message. Returning
`impl Stream<Item = T>` makes the action a **generator**. A non-`async` function runs on tokio's
blocking thread pool.

**Options:** `#[action(name = "..", description = "..", collections = [..], locks = [..],
concurrency = "serial" | "parallel", auto_locks = false)]`.

### The task

| `Task` method | |
|---|---|
| `progress(percent, message)` | progress, shown live |
| `log(message)`, `log_level(level, message)` | a log line on the task |
| `pausepoint().await` | pause here if a person paused the task |
| `now()`, `random(n)`, `sleep(d).await` | time, randomness and sleeping, **recorded** in the journal ([durable execution](#durable-execution)) |
| `id()`, `user()`, `org()` | who and what this task is |
| `Task::local()` | a stand-in for calling an action directly in tests |

## Connecting

| Variable | Effect |
|---|---|
| `FAKTS_URL` (or `ARKITEKT_URL`) | The server. Defaults to `https://go.arkitekt.live`. |
| `FAKTS_TOKEN` | `client_id:refresh_token`: connect without the device-code prompt, e.g. in a container |
| `FAKTS_ALLOW_INSECURE_TRANSPORT=1` | Allow plain `http://` to a non-loopback server |
| `ARKITEKT_DEVICE_ID` | Override this machine's identity |
| `ARKITEKT_MESH=1` / `native`, `ARKITEKT_MESH_PROXY` | Reach services that are only on the [mesh](/docs/concepts/security/mesh) |

For more control, build `ConnectOptions` (`.url(..)`, `.no_cache()`, `.force()`) and use
`app.connect_with(opts)`. Credentials are cached per app and server under your state directory
(e.g. `~/.local/state/arkitekt/cache/`, readable only by you). The file is separate from the Python
client's cache, because both rotate their refresh tokens.

## Durable execution [#durable-execution]

The Rust agent implements the delivery half of [durable
execution](/docs/concepts/durable-execution), but not the workflow half yet.

**What it does:**

- It keeps a local **write-ahead journal** (SQLite, `<app>.journal.db` in the working directory)
  of every task event and state change, in one order. Anything the server has not acknowledged is
  re-sent after a reconnect or a restart.
- It records `task.now()`, `task.random(n)` and `task.sleep(d)` as effects in the journal. This is
  the groundwork for replay.

**What it does not do yet:**

- Rust actions register as **plain** actions with no `effects` claim. If the agent dies while a
  task runs, the task ends **LOST** and the caller decides, as for any plain Python action.
- There is no `#[workflow]`, no `task.call`, and no `task.record` / `retry` / `hold` / `guard`.
  Orchestration that must survive a crash belongs in a
  [Python workflow](/docs/guides/python/durable-execution), which can call Rust actions like any
  others.

## Status [#status]

| Implemented | Not yet |
|---|---|
| Discovery, device-code login, rotating refresh tokens, cache | The redeem grant for headless deployment (use `FAKTS_TOKEN`) |
| `#[action]` with typed ports, defaults, docs, structures, tuples, `Result` and streams | Workflows (actions calling actions) and `effects` claims |
| Cancel, interrupt, pause/resume/step, progress, logs, reconnect with backoff | GraphQL subscriptions |
| States with locks, startup/background/shutdown hooks | Structures inside states |
| The write-ahead journal and resend after restart | Other Mikro data types (tables, files, meshes) and multiscale pyramids |
| Memory structures | Clients for other services (unlok, fluss, kabinet, …) |
| Mikro array datasets, LiveKit streams | |
| Serving over HTTP, tested against the Python implementation | |

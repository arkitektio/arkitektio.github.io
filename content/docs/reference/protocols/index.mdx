The [Python](/docs/guides/python), [Rust](/docs/get-started/next-steps/first-rust-app) and
[Kotlin](/docs/guides/kotlin) clients are conveniences. Underneath, an app talks to the platform
over plain HTTP and one WebSocket, in JSON. This section describes those exchanges directly, for
when you want to write a client in another language, debug one, or understand what the libraries
do for you.

## The one interface an app implements

An app that offers actions has to implement exactly one interface: the **agent**. An agent is a
process that holds a WebSocket open to [Rekuest](/docs/concepts/services/rekuest), says what it can
do, and runs the tasks it is handed.

Everything in the [shared concepts](/docs/concepts/building/shared-concepts) reduces to messages on that one
socket:

| Concept | On the wire |
|---|---|
| The app and its actions | The declaration in the first frame, `REGISTER` |
| A task | An `ASSIGN` from the server, answered with `YIELD` and `COMPLETED` |
| Progress, logs, pause, cancel | Further frames about the same task |
| State | `STATE_PATCH` frames, one per change |
| Bloks | Part of the declaration |

There is no second channel an app must serve. It opens no port and needs no public address: the
agent always dials out, which is why an app runs unchanged behind a lab firewall, in a container or
on a microcontroller.

## What comes before: the login

Before it can open the socket, the app needs two things: a **token** that says who it is, and the
**address** of Rekuest on this deployment. Both come from one HTTP flow,
[Fakts](/docs/concepts/services/service-discovery). The app presents its manifest, a person approves it, and
the server answers with a token and the addresses of the services the app asked for.

```text
   app                         Lok (Fakts)                      Rekuest
    │                               │                               │
    │ 1. discover, present manifest │                               │
    │ ─────────────────────────────►│                               │
    │        a person approves      │                               │
    │ ◄─────────────────────────────│                               │
    │   token + service addresses   │                               │
    │                               │                               │
    │ 2. open  wss://…/agi   REGISTER{token, declaration}           │
    │ ─────────────────────────────────────────────────────────────►│
    │ ◄──────────────────────────────────────────────────── INIT    │
    │ ◄──────────────────────────────────────────────────── ASSIGN  │
    │ ─── YIELD, COMPLETED ────────────────────────────────────────►│
```

So a complete client is two protocols:

1. **[Fakts](/docs/reference/protocols/fakts)**, over HTTP: discovery, device authorization, token
   refresh. Used once at startup and then to refresh the token.
2. **[The agent protocol](/docs/reference/protocols/agent)**, over a WebSocket: registration, tasks,
   state. Open for as long as the app runs.

## What is optional

Anything else an app does is a choice, not a requirement:

- **Calling a service.** Each [service](/docs/concepts/services) such as Mikro has a
  [GraphQL](/docs/concepts/services/graphql) API. An app that reads or writes data uses it with the same
  token. An app that only moves a stage never does.
- **Calling other actions.** A workflow asks for child tasks over the same agent socket.
- **State, locks, bloks, shelved memory.** All are extra frames or extra fields. An agent that
  sends none of them is still a complete agent.

A script that only *calls* the platform, and offers nothing, needs the login and GraphQL but no
agent.

## Reference implementations

The frames are defined once and checked against every implementation:

| | |
|---|---|
| [`rekuest-protocol`](https://github.com/arkitektio/arkirust/tree/main/crates/rekuest-protocol) | Every frame as Rust types, `no_std`. Its `agent_wire_examples.json` holds a canonical example of each frame, generated by the server. |
| [`rekuest-agentd`](https://github.com/arkitektio/rekuest-agentd) | The server side of the agent socket, with the design documents and a black-box conformance suite you can run a new agent against. |
| [`AgentProtocol.kt`](https://github.com/arkitektio/arkitekt-kotlin/blob/main/src/main/kotlin/live/arkitekt/AgentProtocol.kt) | The smallest complete client: one file, actions only. A good template for a new language. |

Not every program offers actions. An upload script, an analysis notebook, a CI job that starts a
workflow, a dashboard that reads results: these only **use** the platform. They log in, get
clients for the services they need, do their work and leave. Nobody can call them, and nothing is
registered.

That is the other direction from [building an app](/docs/guides/app-kinds), and it is much lighter.
There is no project, no packaging and no agent: an import and a `with` block.

```python
from arkitekt import connect
from mikro import Mikro

with connect(Mikro) as mikro:
    folder = mikro.create_folder(name="examples")
```

Behind that line is still an app: `connect(Mikro)` declares one named after your script, logs it
in (asking you to approve it the first time) and hands you the clients. The data you create is
attributed to you, through that script.

## Which pattern?

| Pattern | Use it when |
|---|---|
| [Script](/docs/guides/connect/script) | A program does its job and exits: upload data, export results, a batch analysis |
| [Notebook](/docs/guides/connect/notebook) | You explore interactively in Jupyter and want to stay connected across cells |
| [Drive actions from code](/docs/guides/connect/drive-actions) | Your code starts tasks on other apps: run a segmentation, move a stage, by id |
| [Reuse an app's declaration](/docs/guides/connect/reuse-app) | A tool, test or admin script needs exactly the clients and types an app of yours uses |
| [Unattended](/docs/guides/connect/unattended) | It runs where nobody can approve a login: CI, cron, a container, a remote machine |
| [Other languages and raw protocols](/docs/guides/connect/other-languages) | Your code is Rust, or a language without a client |

## When it should be an app instead

A program that only connects is **not resumed** if it dies, and **nobody can call it**. Turn it
into an [app](/docs/guides/app-kinds) when:

- it orchestrates several actions and a crash halfway would hurt: make it a
  [workflow](/docs/guides/app-kinds/workflow);
- others should be able to run it from Orkestrator or a workflow: make it a
  [plugin](/docs/guides/app-kinds/plugin);
- it holds a device or a live program others need: a [device](/docs/guides/app-kinds/device) or an app
  [inside your own program](/docs/guides/app-kinds/host-program).

## Language support

| Pattern | Python | Rust | Kotlin |
|---|---|---|---|
| Script, notebook | `connect(Mikro)` | `arkitekt::easy(..).connect()` | not yet |
| Drive actions | `connect(RekuestCaller)` | no caller helper yet | not yet |
| Unattended | mandate key, token, saved login | mandate key, token, saved login | saved login only |

Any other language can use the platform over its [bare protocols](/docs/reference/protocols): a login
over HTTP, then the services' GraphQL APIs.

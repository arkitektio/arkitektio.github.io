The **Mesh** step of the wizard (or `--mesh` on the command line) decides whether the hub can be
reached across networks through the [Arkitekt mesh](/docs/concepts/topology#arkitekt-mesh):

- **No mesh** (`none`): the hub stays on the addresses you picked.
- **Join the organization's mesh** (`coordination`): Konstruktor asks the coordination server for a
  mesh key while it authorizes the hub, and runs a mesh sidecar next to the gateway.
- **Use a key I already have** (`manual`): paste a pre-authorized key and the control server URL,
  for a coordinator you run yourself (`--mesh-key`, or better `KONSTRUKTOR_MESH_KEY`, and `--mesh-coord-url`).

Joining is not the same as being advertised. Once the hub is up and has its mesh address, add that
address on the dashboard's address list and **Authorize** again, so apps arriving over the mesh are
told where to find the hub. What the mesh does and why it is the secure default is explained in
[The Mesh](/docs/concepts/security/mesh).

## Local-network advertising (removed) [#advertising]

<Callout type="warn" title="This feature was removed">

  Earlier versions of Arkitekt could **advertise** the platform on your local network with a UDP
  broadcast so that apps could discover it without knowing its IP address. Local networks turned out
  to be too much of a mess (firewalls, changing addresses, blocked broadcasts, VPNs) for that to be
  reliable, and it only ever worked within a single LAN. Apps now discover a hub by the addresses it
  advertises, and across networks through the [mesh](/docs/concepts/topology#arkitekt-mesh).

</Callout>

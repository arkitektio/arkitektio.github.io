The [arkitekt repository](https://github.com/arkitektio/arkitekt/tree/main/examples) has a folder
of small, self-contained example apps. Each one is a single file that does one realistic thing:
measuring nuclei, driving a microscope stage, uploading a z-stack, detecting spikes in a trace.

These tutorials go through them one at a time. Each page shows the whole example, explains what
every part of it is for, and ends with something to try. Read them in order the first time. Later
pages assume you know what the earlier ones explained.

<Prerequisites>

- [uv](https://docs.astral.sh/uv/) installed, or a Python 3.11+ environment with [arkitekt installed](/docs/guides/python/installation)
- A server to connect to, for the steps that call the app from Orkestrator
- Ideally, [Your first app](/docs/get-started/next-steps/first-python-app) done once, so `arkitekt run dev` is familiar

</Prerequisites>

## Getting the examples

Clone the repository and change into it:

```bash
git clone https://github.com/arkitektio/arkitekt.git
cd arkitekt
```

Every example starts with a [PEP 723](https://peps.python.org/pep-0723/) header that lists what it
needs:

```python
# /// script
# requires-python = ">=3.11"
# dependencies = ["arkitekt[rekuest]>=19"]
# ///
```

`uv` reads this header and builds a throwaway environment with exactly those packages, so there is
nothing to install by hand:

```bash
uv run --script examples/hello.py
```

The script connects to the server in `$FAKTS_URL`. To connect somewhere else, set that variable or
change the call at the bottom of the file to `run(app, url="localhost")`. The first run opens a
browser so you can log in. On a machine without a browser, pass `headless=True` and you get a
device code to approve instead.

<Callout type="info" title="Trying an action without a server">

Most of the examples that *offer* actions can be tried with no server at all.
`arkitekt call local` starts the app the same way a run would, calls one action and prints what it
returns:

```bash
uv run --with "arkitekt[rekuest]" arkitekt call local greet examples/hello.py -a name=Ada
```

Each page shows the command for its example. It is the fastest way to see what the code does
before you connect it to anything.

</Callout>

## Two directions

An app does one of two things with the platform:

- It **offers** actions. `run(app)` connects, registers the app's actions and waits for tasks until
  you stop it. Other apps, workflows and people in Orkestrator call it.
- It **calls** services. `connect(Mikro)` connects, hands you the clients you named (Mikro for
  images, Elektro for traces, …), and disconnects when your script is done.

Most examples show one direction or the other, and the pages are grouped that way.

## The tutorials

| Page | Examples | What you learn |
|---|---|---|
| [Actions from functions](/docs/guides/python/examples/actions) | `hello.py`, `measure_nuclei.py` | `@app.action`, how a signature becomes a form, progress, `@app.model` results |
| [A device with live state](/docs/guides/python/examples/device-state) | `microscope_stage.py`, `typed_context.py` | `@app.state`, `@app.startup`, `@app.background`, per-installation config with `app_context` |
| [Arrays between actions](/docs/guides/python/examples/in-memory) | `in_memory_pipeline.py` | `app.memory_structure`: passing numpy arrays between actions without storing them |
| [Uploading data from a script](/docs/guides/python/examples/uploads) | `upload_cells3d.py`, `upload_nifti.py`, `read_with_bioio.py` | `connect(Mikro)`, Mikro datasets, pyramids, contrast anchors, getting axis order right |
| [Actions on stored data](/docs/guides/python/examples/stored-data) | `denoise_volume.py`, `upload_trace.py`, `detect_spikes.py` | Specs like `Volume`, injected clients, derivation edges, Elektro sessions |
| [Embedding in your own program](/docs/guides/python/examples/embedding) | `embedded_host.py` | `run_detached`, listeners, state dropdowns, actions registered at runtime |
| [When an agent dies](/docs/guides/python/examples/recovery) | `recovery/` | `effects=`, `@app.workflow`, `AgentLost`, `task.retry`, `task.hold`, `task.guard` |

The examples that use Mikro or Elektro need those services deployed on your server. The first three
pages need nothing but arkitekt itself.

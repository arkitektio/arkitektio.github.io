The examples so far **offered** actions. These three go the other way: they are plain scripts that
**call** a service, upload an image into [Mikro](/docs/concepts/services/mikro), and exit. Once the
data is in Mikro, every app on the server can use it, and the next page writes actions that do.

<Prerequisites>

- A server with Mikro deployed
- [Actions from functions](/docs/guides/python/examples/actions)

</Prerequisites>

<Learn>

- Get a client with `connect(Mikro)`
- Create a Mikro dataset, with a resolution pyramid and per-channel contrast
- Name axes so that Mikro and the viewers understand them
- Avoid the two common axis-order mistakes: NIfTI's reversed order and bioio's padded dimensions

</Learn>

## `upload_cells3d.py`: a z-stack with a pyramid

```python title="upload_cells3d.py"
# /// script
# requires-python = ">=3.11"
# dependencies = [
#   "arkitekt[mikro]>=19",
#   "scikit-image>=0.24",
#   "pooch>=1.8",
#   "xarray>=2024.3.0",
#   "numpy>=1.26",
# ]
# ///
"""Calling: a script that uploads an image and then exits.

Run:  uv run --script examples/upload_cells3d.py

`connect(Mikro)` is the other direction from `run`: it hands you the clients you
name. Nothing connects until the `with` block is entered.

The image is scikit-image's `cells3d` — a two-channel (membrane, nuclei) z-stack
of cells, 60 planes of 256x256, fetched through pooch on first use (~80 MB).

Afterwards the dataset is in mikro, with a three-level pyramid so the frontend
can show it without loading the whole volume.
"""

import numpy as np
import xarray as xr
from skimage import data

from arkitekt import connect
from mikro import Mikro, dataset_arrays
from mikro.api.schema import CoordinateAnchorInput


def main() -> None:
    """Fetch the sample stack and put it into mikro."""
    # cells3d comes back as (z, c, y, x); mikro wants its axes ordered
    # time -> channel -> space, so the channel axis moves in front.
    raw = data.cells3d()
    volume = xr.DataArray(
        np.moveaxis(raw, 1, 0).astype("uint16"), dims=("c", "z", "y", "x")
    )

    with connect(Mikro, identifier="cells3d-upload") as mikro:
        folder = mikro.create_folder(name="examples")

        # `data` *is* level 0 and `scales` only what is coarser than it —
        # passing the base in both would upload it twice.
        level_zero, scales = dataset_arrays(volume, levels=3, method="mean")

        dataset = mikro.create_array_dataset(
            data=level_zero,
            scales=scales,
            name="cells3d",
            axes=["c", "z", "y", "x"],
            folder=folder.id,
            # One histogram per channel: membrane and nuclei get their own
            # contrast limits rather than a shared, wrong one.
            anchors=CoordinateAnchorInput.histogram_anchors(volume),
        )

        # A scene is what the frontend renders. Its kind is inferred from what
        # was recorded (a z axis makes this a volume), so nothing restates it.
        dataset.stage(name="Default")
        print(f"uploaded {dataset.id}: {dataset.data.shape}")


if __name__ == "__main__":
    main()
```

### `connect`: the calling direction

```python
with connect(Mikro, identifier="cells3d-upload") as mikro:
```

`connect` is the counterpart of `run`. You name the client classes you need, and it gives you
them, connected:

- **Nothing connects before the `with` block.** Entering it logs in (with the browser the first
  time) and connects. Leaving it disconnects.
- **One client gives one client. Several give a tuple**, in the order you named them:
  `connect(Mikro, Elektro) as (mikro, elektro)`.
- The identifier, `"cells3d-upload"`, is the app you authorize on the server. It is how the server
  knows which script uploaded what. Without `identifier=` it is the script's file name.

There is no `@app.action` and no `run`. The script does its work and ends.

### Axis order

```python
raw = data.cells3d()                     # (z, c, y, x)
volume = xr.DataArray(np.moveaxis(raw, 1, 0).astype("uint16"), dims=("c", "z", "y", "x"))
```

Mikro expects axes in the order **time, then channel, then space** (`t`, `c`, `z`, `y`, `x`).
scikit-image delivers this stack as `(z, c, y, x)`, so the channel axis is moved to the front. The
array is wrapped in an `xarray.DataArray` so that every axis has a name, and the names travel with
the data.

### A pyramid

```python
level_zero, scales = dataset_arrays(volume, levels=3, method="mean")
```

A 60 × 256 × 256 stack with two channels is small, but images are often far larger than a browser
can load at once. `dataset_arrays` builds downsampled copies: `level_zero` is the full resolution,
and `scales` holds the coarser levels. A viewer shows the coarse level first and fetches detail as
you zoom in. As the comment in the code notes, `data=` already is level 0, so `scales` holds only
the levels below it.

### Contrast per channel

```python
anchors=CoordinateAnchorInput.histogram_anchors(volume),
```

The membrane and nuclei channels have very different intensities. One shared contrast range would
make one of them look washed out or black. `histogram_anchors` computes a histogram for each channel
and stores it with the dataset, so each channel is displayed with its own range.

### A scene to look at

```python
dataset.stage(name="Default")
```

A dataset is the stored data. A **scene** is what a viewer renders. `stage` creates one with
sensible defaults. Mikro sees the `z` axis and sets the scene up as a volume, so you don't have to
say so.

## `upload_nifti.py`: reversed axes

```python title="upload_nifti.py"
# /// script
# requires-python = ">=3.11"
# dependencies = [
#   "arkitekt[mikro]>=19",
#   "nibabel>=5.2",
#   "xarray>=2024.3.0",
#   "numpy>=1.26",
# ]
# ///
"""Calling: a NIfTI volume from disk into mikro.

Run:  uv run --script examples/upload_nifti.py [volume.nii.gz]

With no argument a small synthetic brain-shaped volume is written to a temp
directory first, so the example runs on any machine.

The one thing worth care: NIfTI indexes its data (i, j, k) with i fastest, while
mikro names axes outermost-first. So the array is reversed into (z, y, x) — the
same reversal every NIfTI ingest needs, and the usual way a volume gets silently
transposed.
"""

import sys
import tempfile
from pathlib import Path

import nibabel as nib
import numpy as np
import xarray as xr

from arkitekt import connect
from mikro import Mikro
from mikro.api.schema import CoordinateAnchorInput


def synthesise(path: Path) -> Path:
    """Write a small NIfTI so the example has something to read."""
    # Built in NIfTI's own (i, j, k) order, i fastest — 64 x 64 x 48.
    i, j, k = np.mgrid[0:64, 0:64, 0:48]
    ball = ((i - 32) ** 2 + (j - 32) ** 2 + (k - 24) ** 2) < 20**2
    data = (ball * 800 + np.random.default_rng(0).normal(0, 30, ball.shape)).astype(
        "float32"
    )
    nib.save(nib.Nifti1Image(data, affine=np.diag([1.0, 1.0, 2.0, 1.0])), path)
    return path


def main(path: Path) -> None:
    """Read the volume and upload it as a (z, y, x) dataset."""
    image = nib.load(path)
    # (i, j, k) -> (z, y, x): reversed, not transposed by name.
    array = np.asarray(image.dataobj).T
    print(f"{path.name}: {image.shape} (i,j,k) -> {array.shape} (z,y,x)")
    volume = xr.DataArray(array, dims=("z", "y", "x"))

    with connect(Mikro, identifier="nifti-upload") as mikro:
        dataset = mikro.create_array_dataset(
            data=volume,
            scales=[],
            name=path.name,
            axes=["z", "y", "x"],
            anchors=[CoordinateAnchorInput.histogram_anchor(volume)],
        )
        dataset.stage(name="Default")
        print(f"uploaded {dataset.id}: {dataset.data.shape}")


if __name__ == "__main__":
    if len(sys.argv) > 1:
        main(Path(sys.argv[1]))
    else:
        with tempfile.TemporaryDirectory() as tmp:
            main(synthesise(Path(tmp) / "synthetic.nii.gz"))
```

The only new thing here is one line:

```python
array = np.asarray(image.dataobj).T
```

NIfTI indexes its data as `(i, j, k)`, with `i` the fastest-changing index. Mikro names axes from
the outermost to the innermost. So the array has to be **reversed**, `(i, j, k)` into `(k, j, i)`,
which is `(z, y, x)`. `.T` on a numpy array reverses all its axes, which is exactly that.

Getting this wrong doesn't raise an error. The upload succeeds and the volume looks transposed. Every
NIfTI import needs this reversal, so it is worth getting right once.

When you run the script without an argument, it first writes a small synthetic volume (a ball in
noise) to a temporary directory. Pass the path of a `.nii` or `.nii.gz` file to upload your own.

## `read_with_bioio.py`: dropping padded dimensions

```python title="read_with_bioio.py"
# /// script
# requires-python = ">=3.11"
# dependencies = [
#   "arkitekt[mikro]>=19",
#   "bioio>=3.5",
#   "bioio-ome-tiff>=1.4",
#   "tifffile>=2024.5.22",
#   "xarray>=2024.3.0",
#   "numpy>=1.26",
# ]
# ///
"""Calling: whatever bioio can read, into mikro.

Run:  uv run --script examples/read_with_bioio.py [image.ome.tiff]

bioio is the reader front-end: one API over many formats, each format a plugin.
Only `bioio-ome-tiff` is installed here on purpose — `bioio-bioformats` would
pull a JRE on first import, which is not what a first example should do.

With no argument a small OME-TIFF is written with tifffile first.

bioio always reports five dimensions, `TCZYX`, padding the ones the file does
not have. Size-1 padding is dropped here rather than uploaded: an axis mikro
does not need is an axis that has to be explained later.
"""

import sys
import tempfile
from pathlib import Path

import numpy as np
import tifffile
import xarray as xr
from bioio import BioImage

from arkitekt import connect
from mikro import Mikro
from mikro.api.schema import CoordinateAnchorInput


def synthesise(path: Path) -> Path:
    """Write a small two-channel z-stack as an OME-TIFF."""
    rng = np.random.default_rng(3)
    stack = rng.poisson(40, (2, 12, 128, 128)).astype("uint16")
    tifffile.imwrite(path, stack, metadata={"axes": "CZYX"}, ome=True)
    return path


def main(path: Path) -> None:
    """Read with bioio and upload the dimensions the file actually has."""
    image = BioImage(path)
    array = image.get_image_data(image.dims.order)  # "TCZYX"

    # Drop the padded singletons, keep the names for the ones that survive.
    kept = [
        (name.lower(), size)
        for name, size in zip(image.dims.order, array.shape, strict=True)
        if size > 1
    ]
    squeezed = xr.DataArray(
        array.reshape([size for _, size in kept]), dims=[name for name, _ in kept]
    )
    print(f"{path.name}: {image.dims.order} {array.shape} -> {squeezed.dims}")

    with connect(Mikro, identifier="bioio-upload") as mikro:
        dataset = mikro.create_array_dataset(
            data=squeezed,
            scales=[],
            name=path.name,
            # Bare names are enough: mikro knows t is time, c channel, zyx space.
            axes=list(squeezed.dims),
            anchors=CoordinateAnchorInput.histogram_anchors(squeezed),
        )
        dataset.stage(name="Default")
        print(f"uploaded {dataset.id}: {dataset.data.shape}")


if __name__ == "__main__":
    if len(sys.argv) > 1:
        main(Path(sys.argv[1]))
    else:
        with tempfile.TemporaryDirectory() as tmp:
            main(synthesise(Path(tmp) / "synthetic.ome.tiff"))
```

[bioio](https://github.com/bioio-devs/bioio) reads many microscopy formats through one API, with a
plugin per format. This example installs only the OME-TIFF plugin. The Bio-Formats plugin would
download a Java runtime the first time, which is more than a first example needs.

bioio always returns **five** dimensions, `TCZYX`. A file without a time axis still gets a `T` of
size 1. The script removes those size-1 axes before uploading:

```python
kept = [(name.lower(), size) for name, size in zip(image.dims.order, array.shape, strict=True) if size > 1]
```

An axis of size 1 that Mikro doesn't need is an axis every later action has to deal with. Dropping
it at the start keeps the dataset as simple as the data.

The axis names are lowercased (`"C"` becomes `"c"`) and passed as plain strings. Mikro recognises
`t` as time, `c` as channel and `z`, `y`, `x` as space.

## Try it

Each script runs on its own, with test data if you give it no file:

```bash
uv run --script examples/upload_cells3d.py       # downloads cells3d (~80 MB) on first use
uv run --script examples/upload_nifti.py         # or: ... upload_nifti.py brain.nii.gz
uv run --script examples/read_with_bioio.py      # or: ... read_with_bioio.py image.ome.tiff
```

Each one prints the id and shape of the dataset it created. Open Mikro in Orkestrator: `cells3d`
is in the *examples* folder, with its two channels shown in their own contrast ranges.

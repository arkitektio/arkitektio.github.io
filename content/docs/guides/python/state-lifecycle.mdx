A task lives for one call. A device connection, a loaded model or the position of a stage lives as
long as the app. Arkitekt gives each of these its own declaration, so the runtime knows when to
create it, who may see it and how to hand it to your actions.

| You have… | Declare it with | Built by | Visible to other apps and the UI? |
|---|---|---|---|
| values others should watch change | `@app.state` | an `@app.startup` hook that returns it | **yes**, published live |
| heavy or private objects (a model, a device handle) | `@app.context` | an `@app.startup` hook that returns it | no |
| configuration of this installation (a path, a pixel size) | `App(app_context=Setup)` | you, via `run(app, context=...)` | no |
| work that runs as long as the app does | `@app.background` | the runtime | no |

All of them reach an action the same way: by [annotation](/docs/concepts/python/core-concepts#injection-by-annotation).

## Startup and shutdown

`@app.startup` runs when the agent starts providing, before the first task. **What it returns sets
up the app's states and contexts**: return an instance of an `@app.state` or `@app.context` class
(or several, as a tuple, when one hook sets up more than one) and that instance is what actions receive. `@app.shutdown` runs when the
agent stops providing.

```python
from dataclasses import dataclass

from arkitekt import App

app = App("camera", "0.1.0")


@app.context
@dataclass
class Camera:
    """The open device. Not published: only this app uses it."""

    handle: object


@app.startup
def open_camera() -> Camera:
    return Camera(handle=open_device("/dev/cam0"))


@app.shutdown
def close_camera(camera: Camera) -> None:
    camera.handle.close()
```

Do this work in hooks, **not at module level**. The CLI imports your module to inspect and package
it, and `arkitekt run dev` re-imports it on every reload.

## Live state: `@app.state`

A class decorated with `@app.state` is **published**. The platform keeps a copy, the UI shows it
live, and other apps can observe it or [guard](/docs/guides/python/durable-execution#guard) on
it. When an action changes an attribute, the change is sent as a patch, so nobody has to poll an
action to find out where the stage is.

```python
from typing import Annotated

import koil
import numpy as np

from arkitekt import App, Description, Task, run

app = App("microscope-stage", "0.1.0")


@app.state
class StagePosition:
    """Where the stage is, in micrometers, and whether it is settled."""

    x_um: float = 0.0
    y_um: float = 0.0
    moving: bool = False


@app.startup
def home_the_stage() -> StagePosition:
    return StagePosition()


@app.action
def move_to(
    state: StagePosition,
    x_um: Annotated[float, Description("Target x, in micrometers")],
    y_um: Annotated[float, Description("Target y, in micrometers")],
    *,
    task: Task,
) -> float:
    """Move To"""
    start = np.array([state.x_um, state.y_um])
    target = np.array([x_um, y_um])
    state.moving = True
    for step in range(1, 21):
        state.x_um, state.y_um = start + (target - start) * step / 20   # published as it changes
        task.progress(step * 5)
        koil.sleep(0.05)
    state.moving = False
    return float(np.linalg.norm(target - start))


@app.background
def drift(state: StagePosition) -> None:
    """Thermal drift, once a second."""
    rng = np.random.default_rng(0)
    while True:
        if not state.moving:
            state.x_um += float(rng.normal(0, 0.01))
        koil.sleep(1)


if __name__ == "__main__":
    run(app)
```

Every action and hook annotated with `StagePosition` receives **the same instance**. Options:

| Option | Meaning |
|---|---|
| `name=` | The key the state is offered under (default: the class name). Another app's protocol refers to it by this name. |
| `publish_interval=` | Seconds between published updates (default `0.1`). Changes in between are coalesced. |
| `required_locks=` | Locks an action must hold to change the state, so two tasks cannot move the stage at once. |

Keep state **small and descriptive**: positions, flags, a barcode, counters. It is published on
every change and recorded in the agent's journal, so it is the wrong place for a model or an image.

## Private shared objects: `@app.context`

A context is shared by the actions of one agent but never published. Use it for things that are
expensive to build or meaningless outside the process: a loaded neural network, a device driver, a
database connection.

```python
from dataclasses import dataclass

from arkitekt import App
from mikro import mikro_service
from mikro.arkitekt.specs import Image, LabelMask

app = App("segmenter", "0.1.0", services=[mikro_service])


@app.context
@dataclass
class Model:
    net: object


@app.startup
def load_model() -> Model:
    return Model(net=load_weights("model.pt"))   # once, at startup


@app.action
def segment(image: Image, model: Model) -> LabelMask:
    """Segment"""
    ...
```

<Callout type="info" title="State or context?">

Ask whether anybody outside this process should see it. A stage position: yes, state. A model:
no, context. Putting a model in `@app.state` would try to publish it.

</Callout>

## Per-installation configuration: `app_context` [#app-context]

Some values describe *this installation* rather than a call: which directory this machine writes to,
the pixel size of this microscope. Callers should not pass them on every call, and they should not
be hard-coded. Declare a class as the app's context and pass an instance to `run`:

```python
import sys
from dataclasses import dataclass
from pathlib import Path

from arkitekt import App, run


@dataclass
class Setup:
    image_dir: Path
    pixel_size_um: float


app = App("acquire", "0.1.0", app_context=Setup)   # an App[Setup]


@app.action
def list_images(setup: Setup) -> list[str]:
    """List Images"""
    return sorted(p.name for p in setup.image_dir.glob("*.tif"))


if __name__ == "__main__":
    run(app, context=Setup(image_dir=Path(sys.argv[1]), pixel_size_um=0.1))
```

`context=` is then **required**. Leaving it out fails before anything connects, and a type checker
flags it too. On the CLI, pass it as `--context module:attr` (an instance, or a zero-argument
callable returning one) or `--context-file config.yaml` (validated by the class, which must then be
a pydantic model).

## Background tasks

`@app.background` functions start when the agent starts providing and run until it stops. Use them
for polling hardware, watching a folder or keeping state fresh. They receive states and contexts by
annotation like actions do. They are not tasks: nobody called them, so they have no `task` and
report no progress.

<Callout type="warn" title="Humans first">

Background work should keep the app's own view of the world current. It should not start experiments
on its own. Arkitekt's model is that every task is started by a person or by a workflow a person
started. See [Humans first](/docs/concepts/philosophy/humans-first).

</Callout>

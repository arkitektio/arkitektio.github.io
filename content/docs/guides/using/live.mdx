You build a workflow that watches the folder your microscope writes to and analyses each image as
soon as it lands there, instead of in a batch afterwards. Why Arkitekt is built for this is
explained in [Real-time](/docs/concepts/philosophy#everything-everywhere-all-at-once).

<Prerequisites>

- You can build and run a workflow: [Your first workflow](/docs/guides/first-workflow)
- The segmentation workflow from [Bridging deep learning](/docs/guides/using/deep-learning), or
  another segmentation action on your hub
- [Gucker](/docs/guides/apps/gucker) installed on the computer that receives the microscope's files
- An app that converts your microscope's file format into images. The App Store has converters for
  OME-TIFF, LIF, ND2, OBF and anything Bio-Formats reads.

</Prerequisites>

## How the stream works

Most actions take an input and return a result once. A **stream action** yields results many
times, over time ([Action can establish streams](/docs/concepts/terminology#action-can-establish-streams)).
Gucker's **Stream Files** action is one: it yields every new file that appears in a folder.

Workflows pass items on as they arrive
([Data flows as a stream](/docs/concepts/terminology#data-flows-as-a-stream)). Put a stream action
first, and every node after it runs once per file, while the acquisition continues.

## 1. Point Gucker at the microscope's folder

1. Start Gucker (`gucker`, or the binary from its release) and connect it to your hub.
2. Set the **Import** directory to the folder the microscope writes to. Gucker watches it for new
   files.

Details are on the [Gucker page](/docs/guides/apps/gucker#configuration).

## 2. Build the workflow

In the Workflow Designer, chain four nodes:

1. **Stream Files** (Gucker): set it to the Gucker instance that watches your folder. Add a regular
   expression to pick only the files you want, such as `.*.tif` or `.*.nd2`.
2. **Convert**: the converter action for your file format, turning each file into an image.
3. **Segment**: your segmentation action, for example **Segment Fluo2** from segmentor.
4. **Measure**: an action that measures the segmented objects, for example their area.

Connect `Input` and `Output` as in any workflow, and save it.

## 3. Run it during the acquisition

1. Run the workflow from Orkestrator.
2. Start the acquisition. Each file the microscope writes is picked up, converted, segmented and
   measured, and its result appears on the run's page while the next image is being taken.

Test the regular expression on [regex101](https://regex101.com/) against your file names before a
long acquisition.

For a complete example on a real microscope, see the
[Streaming analysis showcase](/docs/legacy/showcases/streaming-workflow). It was made with an older
version of Arkitekt, so its setup steps are outdated.

## Design

The [ImageJ Arkitekt plugin](https://github.com/arkitektio/imagej-arkitekt-plugin) is a native ImageJ2/Fiji plugin, written in
Kotlin and running directly inside Fiji's own JVM. It replaces the earlier MikroJ app, which wrapped Fiji from Python through PyImageJ and required a separate installation.

Once installed, the plugin logs you in to your Arkitekt server, registers the running Fiji instance as an agent, and exposes a set of ImageJ actions
that Arkitekt can invoke remotely: upload the active image, load an image or dataset back into the viewer, sync ROIs, and run image-to-image macros.
Images are transferred as Zarr arrays through the Arkitekt data layer, so no data has to pass through a third process anymore.

Because the plugin lives inside Fiji, it works wherever Fiji works: Windows, Linux and Mac.

## Installation

You need a working Fiji installation. You can download Fiji from [here](https://imagej.net/software/fiji/downloads).
The plugin is tested against the JRE that ships with Fiji, so no separate Java installation is needed.

Each release of the plugin ships in two forms:

<FijiGrid/>

- **Jar (simplest)**: download `arkitekt-plugin-<version>.jar` and drop it into the `plugins/` folder of your Fiji installation (`Fiji.app/plugins/`).
  Delete any older `arkitekt-plugin-*.jar` first. With two versions on the classpath Fiji picks one at random.

- **Zip**: the archive unpacks to a single `arkitekt/` folder inside `plugins/`. Remove a previous install before unpacking:

  ```bash
  rm -rf /path/to/Fiji.app/plugins/arkitekt
  unzip arkitekt-plugin-*.zip -d /path/to/Fiji.app/plugins/
  ```

Restart Fiji afterwards. The plugin shows up in the menu under **Plugins › Arkitekt**.

<Callout type="info" title="Coming from MikroJ?">


MikroJ is no longer maintained. You can uninstall it, and simply start Fiji directly as you normally would. The plugin takes over
the connection to Arkitekt from inside Fiji, so there is no bridge app to start first anymore.


</Callout>

## Usage

Open **Plugins › Arkitekt** in Fiji. You will be asked for the URL of your Arkitekt server (the default is `https://go.arkitekt.live`).
Enter the address of your instance and click **Login**. This opens your browser, where you approve the device login and grant the requested permissions, just
like with any other Arkitekt app.

The login is cached in `~/.arkitekt/fakts_cache.json`, so subsequent starts connect silently. Delete that file to log out and connect to a different server.

Once connected, Fiji appears as an app in Orkestrator and its actions become available to your workflows:

1. _Uploading_:
   The `Upload Image` action takes the currently active image in Fiji and stores it on your Arkitekt server, including the metadata needed to trace its origin.

2. _Showing_:
   The `Show Image` action loads an image stored on the server into the Fiji viewer. The whole image is transferred into Fiji's memory, so you can
   close the browser and keep working on the image.

3. _ROIs_:
   ROIs are synced between Fiji's ROI manager and the Arkitekt server, so regions you draw in Fiji are available in the browser and in other apps.

4. _Macros_:
   Image-to-image ImageJ macros can be exposed as actions, so any existing macro can become a step in an Arkitekt workflow. See the
   [Fiji workflow showcase](/showcase/fiji-workflow) for an example.

Whatever alterations you make to an image in Fiji stay in Fiji until you upload it again. Nothing is written back to the server automatically.

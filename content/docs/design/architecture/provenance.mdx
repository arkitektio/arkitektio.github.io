Arkitekt keeps a sharp line between **you** and **the machine that run the analysis**, and ensures that every change to your data 
is honestly attributed and accounted for.

For this we ensure **provenance-aware audit logging**. Every create, update, and delete on a tracked
record inside one of Arktiekt services is captured as a history update and each updates is attributed to *who* made the change,
*which app* they used, and, crucially, the verified **task** it happened under. This lets anyone ask

> *"Which automated run touched this record, on whose authority, and what exactly did it change? And by the way what else did it touch?"*

<Callout type="info" title="Where this lives">
The task provenance layer is  cryptopgraphically signed by the task-server and verified by the platform's identity layer. While this is not
bulletproof, it is a strong guarantee that the audit trail is not forged or tampered with. 
</Callout>

## What gets recorded

Every change produces a **provenance entry** that carries:

| Field               | Meaning                                                          |
|---------------------|------------------------------------------------------------------|
| `user`              | The human user the change is attributed to.                      |
| `client`            | The app / OAuth client that made the change, if any.             |
| `task`              | The verified task the change ran under, if any.                  |
| `kind`              | `CREATE`, `UPDATE`, or `DELETE`.                                 |
| `date`              | When the change happened.                                        |
| `effectiveChanges`  | The per-field old → new diff for that change.                    |

This is what makes the human-versus-machine distinction concrete. When an agent runs an action on
your behalf, the entry records both facts at once: that the work was **authorized by you**, and
that it was **carried out by a machine**. It never collapses one into the other.

## What is a task?

A **task** groups together every change made during one logical run. In Arkitekt a task and a workflow are ALWAYS first
initiated by a human user, and are always attributed to them. If the task is delegated to an agent,
the agent still carry the trail of the user's authority and the original task identity.

<ProvenanceFlow />

When a user calls a registered function on an agent, the agent receives a single, server-signed
**provenance token** for that one run. While the function executes, every outgoing operation it
makes, every mutation no matter how many, is transparently stamped with that **same** token.
The application code does nothing special; the token is set once and propagates to everything the
function does.



## Tech details, for who wants to know

The Provenance layer for each service is built on three cooperating components, each with a single responsibility:

```
        Rekuest provenance token (signed, EdDSA)
                       │
        ┌──────────────▼───────────────┐
 kante  │  GraphQL transport + context  │   ← carries the request + its context
        └──────────────┬───────────────┘
                       │
        ┌──────────────▼───────────────┐
 authn. │  authentikate                 │   ← verifies the token, resolves the
        │  → user, client, organization │     acting user / client / organization and the task it ran under
        └──────────────┬───────────────┘
                       │
        ┌──────────────▼───────────────┐
 koher. │  koherent                     │   ← stamps every change with user, client,
        │  → attributed history rows    │     and the verified task it ran under (based on django-simple-history)
        └───────────────────────────────┘
```

- **[kante](https://github.com/jhnnsrs/kante)** provides the GraphQL transport and the request
  context the upper layers build on.
- **[authentikate](https://github.com/jhnnsrs/authentikate)** owns identity. It verifies the
  signed provenance token and resolves the acting *user*, *client*, and *organization*. There is
  no bypass for provenance. The signature is always checked.
- **[koherent](https://github.com/jhnnsrs/koherent)** consumes that verified context and turns
  each data change into a durable, attributed history row, building a `Task` from the token's
  claims.

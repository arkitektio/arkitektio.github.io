Not every program offers actions. An analysis script that uploads a result, a notebook that pulls
images from Mikro, or a CI job that starts a workflow only **calls** the platform. For these,
`arkitekt` has `connect`: name the clients you need and get them back, connected.

## `connect(Mikro)`

```python
import numpy as np
import xarray as xr

from arkitekt import connect
from mikro import Mikro, dataset_arrays

volume = xr.DataArray(np.random.rand(1, 20, 256, 256).astype("float32"), dims=("c", "z", "y", "x"))

with connect(Mikro) as mikro:
    folder = mikro.create_folder(name="examples")
    level_zero, scales = dataset_arrays(volume, levels=3, method="mean")
    dataset = mikro.create_array_dataset(
        data=level_zero,
        scales=scales,
        name="random volume",
        axes=["c", "z", "y", "x"],
        folder=folder.id,
    )
    print(dataset.id)
```

- You name **client classes**, the same `Mikro` an action would take by annotation. Behind the
  scenes `connect(Mikro)` declares `App(<the script's file name>, clients=[Mikro])` for you. That
  identifier is what you authorize, and what shows up as the app in the platform. Pass
  `identifier="my-upload-script"` to name it yourself.
- **Nothing connects until the block is entered.** Entering authenticates (opening a browser
  the first time) and connects the clients. Leaving disconnects them. The same `connect(...)` object
  can be entered again.
- **One client gives you that client, several give a tuple** in the order you named them. The
  result is typed, so your editor knows `mikro` is a `Mikro`:

  ```python
  from fluss import Fluss

  with connect(Mikro, Fluss) as (mikro, fluss):
      ...
  ```

It takes the same connection options as `run`: `url=`, `headless=`, `token=`, `mandate_key=`,
`skip_cache=`, `reauth=`, `mesh=` (see [Installation](/docs/develop/python/installation#connecting-to-a-server)).

## Clients: sync and async

Every client exposes each operation twice: a blocking method and an `a`-prefixed coroutine. The
same `connect(...)` works as an `async with`:

```python
from arkitekt import connect
from mikro import Mikro


async def main() -> None:
    async with connect(Mikro) as mikro:
        folder = await mikro.acreate_folder(name="examples")
```

Objects returned by a client are snapshots of the server's state. Changing an attribute locally
changes nothing on the server. Call the corresponding mutation to change the stored object.

## Notebooks: `.enter()`

In Jupyter a `with` block per cell is awkward. `.enter()` connects once and stays connected until
the kernel exits:

```python
from arkitekt import connect
from mikro import Mikro

mikro = connect(Mikro, identifier="notebook").enter()
dataset = mikro.get_array_dataset("1234")   # any operation of the client
```

Running the cell again leaves the previous connection of that app before it connects again, so a
re-run cell does not pile up sessions. Blocking calls work inside the notebook's own event loop.

## Calling actions

Connect `RekuestCaller`, the [Rekuest](/docs/develop/internals/rekuest) client that starts tasks, and
call any action you are allowed to call by its id (copied from Orkestrator):

```python
from rekuest.client.client import RekuestCaller

from arkitekt import AgentLost, connect, retry

with connect(RekuestCaller, identifier="plate-runner") as rekuest:
    result = rekuest.call("<action-id>", x=21)
```

A call from a script is a **root** task: it has no parent, and it is recorded as started by you
through this script.

- **If the agent running it dies**, the call raises `AgentLost`. The top-level `retry(...)` works
  like [`task.retry`](/docs/develop/python/durable-execution#taskretry-try-again-when-it-is-safe):
  `retry(rekuest.call, "<action-id>", x=21, attempts=3, if_started=True)`.
- **If your script dies**, the tasks it started keep running, but nothing waits for their results,
  and the script is not resumed. Orchestration that must survive a crash belongs in an
  [`@app.workflow`](/docs/develop/python/workflows).
- **Inside a running action** you cannot use the client to call. That would create an unrelated root
  task instead of a child, so it raises `RootOnlyCallError`. Use a workflow and its protocol proxies.

## Using an `App` without offering it

When a script needs the same declaration as an app (its clients, its registered structures), pass
the app itself: `connect(app)` instead of `run(app)`. It connects the app's clients but provides
nothing. What you get back is the run, and `require` hands out its clients:

```python
from arkitekt import connect
from mikro import Mikro

from app import app   # your app's declaration

with connect(app) as runtime:
    mikro = runtime.require(Mikro)
```

`connect(app)` takes one app. Client classes it should build although no annotation names them go
into the app, `App(..., clients=[Fluss])`. To hand it client *instances* (a fake in a test, a
client you configured yourself), pass `connect(app, clients=[my_mikro])`.

## Qt applications

A desktop program with its own window, such as a microscope control GUI or a napari plugin, is a
*standalone* app. It both offers actions and owns its event loop. `arkitekt.qt` (the `qt` extra)
provides `QtApp`, a declaration whose actions can run in the Qt event loop, and `MagicBar`, a widget
that runs the app and shows its connection status:

```python
from qtpy import QtWidgets

from arkitekt import connect
from arkitekt.qt import MagicBar, QtApp


class Window(QtWidgets.QWidget):
    def __init__(self) -> None:
        super().__init__()
        self.runtime = connect(app, provide=True)        # provide: offer the app's actions
        self.bar = MagicBar(self.runtime, context=self)  # logs in and starts it on a click


app = QtApp("my-viewer", app_context=Window)            # an action asking for Window gets it
```

`arkitekt create my-viewer --template qt` writes a complete one, with an action that runs in the
Qt loop (`@app.register_in_qt_loop`) to touch the window.

## FastAPI

`arkitekt.serve(app, fastapi_app, ...)` (the `serve` extra) serves an app's actions from an existing
FastAPI application instead of a standalone agent process.

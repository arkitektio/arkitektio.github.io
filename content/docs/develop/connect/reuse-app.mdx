title: Reuse an app's declaration
description: "Connecting with an app you already declared, without offering its actions: connect(app) for maintenance scripts, admin tools and tests that need exactly the clients and types the app uses."
type: guide
---

Sometimes a script belongs to an app. A migration that re-processes what the app stored, an admin
tool that inspects it, a test that needs the same clients the actions get. It should log in **as
that app**, with the same clients and the same registered types, but not offer anything.

## Use it when

- The script works with **an app you already declared**, and should see what its actions see.
- It must **not** register the app's actions or take tasks.

## The shape

Pass the app itself to `connect`, instead of client classes:

```python
from arkitekt import connect
from mikro import Mikro

from app import app            # your app's declaration


with connect(app) as runtime:
    mikro = runtime.require(Mikro)
    for dataset in mikro.get_array_datasets(...):
        ...
```

- `connect(app)` logs in as the app and builds every client the app uses, but **provides nothing**:
  no agent, no actions, no tasks. `run(app)` is the same plus serving the actions.
- `runtime.require(Mikro)` hands out a client. It raises `LookupError` if the app does not use that
  client.
- A client only this script needs, which no annotation in the app names, goes into the app:
  `App(..., clients=[Fluss])`.

## Handing it clients

`connect(app, clients=[...])` takes client **instances** to use instead of building them, matched
by class. That is how a test gives the app a fake, or how you pass a client you configured
yourself. The same `clients=` works on `run`, `serve` and `run_detached`.

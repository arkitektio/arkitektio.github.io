The first time an app connects, a person approves it: a browser opens, they pick an organization
and allow it. That does not work in a CI job, a nightly cron script, a container or a machine you
only reach over SSH. There are four ways around it, from the most to the least convenient for you.

## 1. A saved login

After the first approved login, the session is **kept** (per app identifier, version and server)
and refreshed on its own. A script that ran once by hand on a machine connects without asking from
then on, including from cron on that same machine as the same user.

Good for a scheduled script on a machine you can log in to once. Changing the app's identifier or
version, or `reauth=True`, asks again.

## 2. A headless first login

On a machine without a browser, approve from another device:

```python
with connect(Mikro, headless=True) as mikro:     # prints the link, and a QR code
    ...
```

Nothing opens. The link and code are printed (a QR code too, for approving on a phone). Once
approved, the login is saved as in (1). On the command line, `arkitekt login --headless` does the
same for the app in the current folder.

Good for a remote machine over SSH, or a lab PC whose screen you cannot see.

## 3. A mandate key

A **mandate key** logs the app in with no person at all, as whoever issued the key. Ask whoever
runs your deployment for one, then hand it to the run:

```bash
export FAKTS_URL=https://lab.example.org
export FAKTS_MANDATE_KEY=...             # a secret: keep it in your CI's secret store
python nightly_export.py
```

or in code, `connect(Mikro, mandate_key=...)`. The app logs in again by itself whenever its access
expires.

Good for CI, containers and devices: anywhere a fresh process starts with nothing saved.

## 4. A token

`FAKTS_TOKEN=client_id:refresh_token` (or `token=`) hands over a credential issued earlier. It
works, but a refresh token rotates as it is used, so a copy goes stale. Prefer a mandate key for
anything long-lived.

## What to watch

- **Treat keys and tokens as passwords.** Anything that holds one acts as the person who issued it.
  Keep them out of the repository and out of logs.
- **Ephemeral environments save nothing.** A container's saved login disappears with the container.
  Use a mandate key there, and `skip_cache=True` if nothing should be written.
- **Name the app for the job.** `identifier="nightly-export"` makes it obvious in the platform, and in
  provenance, which job created what.
